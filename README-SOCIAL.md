## ระบบทำอะไรได้

- **ฟีดเสียงลูกค้าเรียลไทม์**: LINE OA, Facebook (แชท+คอมเมนต์), Instagram, Google Maps และช่องทางอื่น (Wongnai/Grab/LINE MAN/TikTok — เพิ่มเองหรือยิงผ่าน Generic Webhook)
- **AI วิเคราะห์ทุกรีวิวอัตโนมัติ**: อารมณ์ ชม/ตำหนิ, คะแนน 0-100, แยกประเด็น, จับชื่อพนักงาน, ช่วงเวลาที่มา, ร่างคำตอบ
- **สรุปอัตโนมัติรายวัน 06:10**: มีปัญหาอะไร ใครทำดี ช่วงเวลาไหนดี ควรทำอะไรต่อ
- **แชทบอท** LINE / Messenger / IG DM — ต่อช่องทาง: ปิด / ร่างให้คนตรวจ / ตอบเองเฉพาะคำถามพบบ่อย (FAQ) / ตอบเองทั้งหมด
  ระบบเรียนรู้คำถามที่ลูกค้าถามซ้ำแล้วเสนอเป็น FAQ ให้กดอนุมัติ · ถ้าโควต้า AI หมด บอทยังตอบคำถามที่ตรง FAQ ได้ (เทียบคำแบบไม่ใช้ AI)
- ล็อกอินด้วยบัญชี `pnl_users` เดียวกับ P&L (เข้าจากหน้ารวมระบบได้เลย)

## ขั้นตอนติดตั้ง (ทำครั้งเดียว)

### 1) ฐานข้อมูล
รัน `jjmk_social_setup.sql` แล้วตามด้วย `jjmk_social_fix_grants.sql` ใน Supabase → SQL Editor
· ใช้ปุ่ม 🚀 ดึงย้อนหลังทั้งหมด = รัน `jjmk_social_posts.sql` เพิ่ม (อยู่ branch `sql` — ไฟล์ SQL ใหม่ไม่เก็บใน branch งาน)

### 2) Edge Functions (2 ตัว) — ทำผ่านเว็บ
Supabase Dashboard → **Edge Functions → Deploy a new function (via Editor)**
- ชื่อ `social-brain` → วางโค้ด (ปุ่ม 📋 ในแอป หรือไฟล์ `supabase/functions/social-brain.ts`) → Deploy
- ชื่อ `social-webhook` → วางโค้ด `social-webhook.ts` → Deploy → เข้า Details → **ปิด Verify JWT** (จำเป็น — LINE/Facebook/Google ยิงเข้ามาตรง ๆ)
- แก้โค้ดครั้งถัดไป: เปิดฟังก์ชันเดิม → วางทับ → Deploy (การ์ดสถานะในแอปจะบอกถ้าเวอร์ชันยังเก่า)

### 4) งานอัตโนมัติ (pg_cron) — **สำคัญ ไม่ทำ = ไม่ดึง/ไม่วิเคราะห์/ไม่สรุปเอง**

### 5) เชื่อมแต่ละช่องทาง
แอป → หน้า **เชื่อมต่อช่องทาง** มี Webhook URL + ปุ่มคัดลอก:
- **LINE OA**: LINE Developers → Messaging API → วาง Webhook URL (`?ch=line`) → เปิด Use webhook → ปิดข้อความตอบกลับอัตโนมัติเดิมใน LINE OA Manager
- **Facebook/Instagram**: ข้อ 8
- **Google Maps**: ใส่ Place ID ของแต่ละสาขา → กด "ดึงรีวิวตอนนี้" ทดสอบ (ระหว่างรอ GBP)
- **ทางลัดทุกแอพ (Apify)**: ข้อ 9
- **ช่องทางอื่น**: ปุ่ม "เพิ่มรีวิวเอง" หรือ Generic Webhook (`?ch=generic` + header `x-webhook-key`)

### 6) Google Places (ใช้ระหว่างรออนุมัติ GBP) — ให้อยู่ในโควต้าฟรี
1. โปรเจกต์ Google Cloud ต้อง**ผูก billing account** (ไม่ผูก = Google ปฏิเสธทุกคำขอ แม้อยู่ในโควต้าฟรี)
2. เปิด **Places API (New)** และ **Places API (Legacy)** — ตัว Legacy ค้นหาไม่เจอให้เปิดจากลิงก์ตรง
   `https://console.cloud.google.com/apis/library/places-backend.googleapis.com` (ไม่เปิด = ได้แค่ 5 รีวิวเด่นซ้ำ ๆ ไม่ได้รีวิวใหม่)
3. จำกัด API key ให้ใช้ได้แค่ 2 API นี้
4. **ตั้งเพดาน**: APIs & Services → Places API (ทั้ง 2 ตัว) → Quotas → จำกัด **ไม่เกิน 30 ครั้ง/วัน** ต่อ API
   (30 × 31 วัน = 930 < ฟรี 1,000) แล้วตั้ง Billing → Budgets & alerts → งบ US$1
   — **งบนี้แค่ส่งอีเมลเตือน ไม่ได้ตัดการใช้งาน** ตัวที่กันเกินได้จริงคือเพดานรายวัน
   · ถ้าหน้า Quotas มีให้ตั้งแค่รายนาที: ตั้งแบบนั้นกันเกินรายเดือนไม่ได้ (1 ครั้ง/นาที = 1,440 ครั้ง/วัน) —
     ต้องพึ่งรอบดึงทุก 3 ชม. ของระบบ + อีเมลเตือนงบ และเปิด Billing → Reports ดูเดือนละครั้ง

### 7) Google Business Profile — รีวิวครบทุกอัน + ตอบรีวิวจากแอป (ฟรี)
1. **ยื่นขอสิทธิ์ API**: https://support.google.com/business/contact/api_default → "Application for Basic API Access"
   ส่งจากอีเมลเจ้าของ/ผู้จัดการ Business Profile + ใส่ Project number ของ Cloud · โปรไฟล์ต้องยืนยันแล้วและเปิดมา 60 วันขึ้นไป + มีเว็บไซต์
   รออนุมัติ **2–6 สัปดาห์** · ตรวจผล: Cloud Console → Quotas ของ 3 API ข้อ 2 ต้องขึ้น 300 ต่อนาที (ยังเป็น 0 = ยังไม่อนุมัติ)
2. เปิด API 3 ตัว: `Google My Business API` · `My Business Account Management API` · `My Business Business Information API`
3. **OAuth consent screen** (Google Auth Platform): External → **Audience → กด "Publish app"** (In production)
   — ถ้าค้างไว้แบบ Testing, Google ตัดสิทธิ์ทุก 7 วันและต้องกดเชื่อมต่อใหม่ทุกสัปดาห์ · บัญชีของร้านเองไม่ต้องผ่าน verification แค่กดผ่านหน้าเตือน "unverified app"
4. Credentials → OAuth client ID (Web application) → Authorized redirect URI:
   `https://aikyxvluaiubdidqxwnd.supabase.co/functions/v1/social-webhook`
5. ตั้ง secrets `GBP_CLIENT_ID` / `GBP_CLIENT_SECRET`
6. แอป → เชื่อมต่อช่องทาง → **เชื่อมต่อบัญชี Google Business ของร้าน** (เฉพาะบัญชีระดับผู้ดูแล/เจ้าของ · ลิงก์ใช้ได้ 15 นาที) → ยินยอม → กด **⟳ ซิงค์รีวิวทั้งหมด**
7. ซิงค์ครั้งแรกจะเจอรายชื่อโปรไฟล์ทั้งหมดที่บัญชีนี้ดูแล — โปรไฟล์ที่ชื่อไม่ตรงกับชื่อสาขาจะ**ยังไม่ถูกดึง**จนกว่าจะเลือกสาขา
   → เลือกสาขาใต้ปุ่มเชื่อมต่อ (โปรไฟล์ที่ไม่ใช่ของร้าน/ซ้ำ เลือก **"🚫 ไม่ดึง"**) → **💾 บันทึกสาขา** → กดซิงค์อีกครั้ง
   · บันทึกสาขาแล้ว รีวิวที่ดึงมาก่อนหน้าของโปรไฟล์นั้นย้ายสาขาตามให้ · เปลี่ยนเป็น "ไม่ดึง" แอปจะถามก่อนลบรีวิวของโปรไฟล์นั้นออกจากระบบ (รีวิวบน Google ไม่หาย)
   · ประวัติย้อนหลังเยอะ ซิงค์รอบเดียวไม่ทัน → แอปวนซิงค์ต่อให้เองจากจุดที่ค้าง (ค้างเกิน 2 ชม. เริ่มใหม่ — ของที่มีแล้วข้ามเร็ว)
   · Google ตอบผิดพลาดชั่วคราว ลองหน้าเดิมใหม่ 3 ครั้ง ยังไม่ได้ = การ์ดสถานะเตือน "ประวัติย้อนหลังยังไม่ครบ" ค้างไว้จนซิงค์ได้ครบ
   · เลือกสาขาให้โปรไฟล์ทีหลัง แอปจะถามว่าจะดึงย้อนหลังเลยไหม (ไม่ดึง = cron ได้แค่รีวิวใหม่ ๆ) · เชื่อมบัญชีใหม่ การเลือกสาขาเดิมยังอยู่
   · โปรไฟล์ของสาขาไหนดึงไม่ได้ สาขานั้นใช้ Place ID แทน — ไม่มี Place ID ของสาขานั้น การ์ดสถานะจะขึ้นแดงว่าไม่ได้รีวิวใหม่เลย

ได้อะไร: รีวิวย้อนหลังทุกอันของทุกสาขา (รวมทุกบัญชีธุรกิจที่ล็อกอินเห็น), คำตอบที่เคยตอบใน Google Maps ขึ้นว่า "ตอบแล้ว" ให้เอง,
ปุ่ม "ส่งตอบกลับ" บนรีวิว Google ใช้งานได้จริง · token เก็บแบบเข้ารหัส (AES-GCM)
เชื่อม GBP แล้ว cron จะใช้ GBP ก่อน (ฟรี) — Places ใช้เฉพาะตอน GBP ยังไม่พร้อม และกันรีวิวซ้ำข้ามสองแหล่งให้แล้ว

### 8) Facebook / Instagram (Meta — ฟรี)
1. Meta for Developers → Webhooks → Page: URL `?ch=facebook` + Verify token ให้ตรง `FB_VERIFY_TOKEN` → subscribe **`messages`, `feed`**
   Instagram: URL `?ch=instagram` → subscribe **`messages`, `comments`**
   (รีวิวเพจ/`ratings` — Meta ปิดไปแล้วตั้งแต่ปี 2025 ใช้ไม่ได้อีก)
2. `FB_PAGE_TOKEN` ต้องเป็น **Page token แบบไม่หมดอายุ**: เอา user token แบบ long-lived ไปขอ Page token (หรือใช้ System User token)
   — token จาก Graph API Explorer หมดอายุในไม่กี่ชั่วโมง (การ์ดสถานะจะเตือนถ้าหมดอายุ)
3. เปลี่ยนแอป Meta เป็น **Live** แล้วทดสอบทักแชท/คอมเมนต์ด้วยบัญชีที่**ไม่มีบทบาทในแอป**
   ถ้าไม่เข้า: ทำ Business Verification + App Review สิทธิ์ `pages_messaging`, `pages_manage_metadata`, `pages_read_engagement`, `pages_manage_engagement`, `instagram_manage_messages`, `instagram_manage_comments`
4. Messenger ส่งหาลูกค้าได้ภายใน 24 ชม. หลังข้อความล่าสุดของลูกค้าเท่านั้น (ระบบแจ้งเหตุผลให้ถ้าส่งไม่ได้)

  - เปลี่ยนกลุ่ม/ล้างกลุ่มใน `news_cfg` (เดิมตั้งกลุ่มไว้แล้ว) → ส่งข้อความสั้นเข้า**กลุ่มเดิม**: "🔔 JJ Social: เปลี่ยนกลุ่มที่รับสรุปรายวันแล้ว โดย <ชื่อผู้ใช้> (<HH:MM เวลาไทย>) — ถ้าไม่ได้สั่งเอง แจ้งผู้ดูแลระบบ"
    (ชื่อผ่าน `lineTxt` ≤40) · ส่งไม่ได้ก็ยังบันทึก · คำตอบมี `old_notified: true|false` (ไม่มีช่องนี้ = ไม่ได้แจ้ง เพราะกลุ่มเดิม/ไม่เคยตั้ง/อ่านค่าเดิมไม่ได้) · ปิดส่งแต่กลุ่มเดิม = ไม่แจ้ง
    · **แจ้งได้วันละ ≤3 ครั้ง** (`social_sys` `news_cfg_note:<วันนี้ไทย>:<n>` — สลับกลุ่มไปมาไม่ทำให้บอทส่งได้ไม่จำกัด) · เกิน = บันทึกได้ `old_notified:false`

**กันส่งซ้ำ/ส่งของปลอม** (ผลตรวจอิสระ 2026-10-08 — `summary` แบบไม่รอผลเรียกได้ด้วยคีย์สาธารณะ แยกจาก cron ไม่ได้):
- ทางไม่รอผล (cron) **ไม่รับ `date`/`span` จากคำขอ** — สรุป/ส่งของเมื่อวานเสมอ
- **ส่งอัตโนมัติเฉพาะ 06:00–07:59 เวลาไทย** (คิดจาก `Date.now()` +7 ชม. · pg_cron เรียก 23:10 UTC = 06:10) — นอกช่วง = ยังสร้างสรุปเก็บไว้ แต่**ไม่จองวัน ไม่ส่ง**
  (`push: {ok:false, skipped:true, reason:"นอกช่วงเวลาส่งอัตโนมัติ (06:00–08:00)"}` ใน heartbeat) — กันคนเรียก `summary` ตอนเที่ยงคืนเพื่อเลือกเวลาส่ง/แย่งจองวันไปก่อน cron
- ก่อนส่ง cron **จองวัน** = insert แถว `social_sys` **`news_push:<วันที่>`** แบบธรรมดา (ไม่ upsert) — ซ้ำ (23505/409) = มีคำขออื่นส่งไปแล้ว → ไม่ส่ง ("ส่งแล้ววันนี้") · จองไม่ได้ = ไม่ส่ง · ส่งแล้วจดผลกลับลงแถวเดิม
- ข้อความ LINE: **ทุกข้อความที่มาจากตาราง** (รีวิว/คอมเมนต์ · สรุป AI · ชื่อสาขา · ชื่อช่องทาง · คำบรรยายโพสต์) ตัดลิงก์/ชื่อโดเมน/IP เป็น `[ลิงก์]` (`lineTxt` — ไม่แตะทศนิยมเช่น 4.5★)
  ลิงก์เดียวในข้อความคือลิงก์แอปท้ายข้อความ · **รอบ 2 (โดเมนภาษาอื่น/หน้าตาเหมือน)** `noLinks`:
  ① ลบอักขระมองไม่เห็น `\p{Cf}` (zero-width · soft hyphen · word joiner · BOM · ทิศทางข้อความ — อีโมจิที่ต่อด้วย ZWJ จะแยกเป็นตัว ๆ) ② ตัวอักษรเต็มความกว้าง U+FF01–FF5E → ASCII
  ③ จุด `。｡․﹒︒` → `.` (**ไม่ใช้ NFKC กับทั้งข้อความ** — สระอำ ำ จะถูกแยก ข้อความไทยเปลี่ยน) ④ ลิงก์ที่มี scheme/`www.`
  ⑤ ชื่อโดเมนทุกภาษา: label = ตัวอักษร/เครื่องหมาย/ตัวเลขภาษาใดก็ได้ · TLD = `xn--…` / a-z ≥2 / `ไทย` / `คอม` (ที่ไม่มีอักษรไทยต่อท้าย) / อักษรภาษาอื่นที่ไม่ใช่ไทย ≥2
  (TLD เป็นอักษรไทยอื่น = ไม่ใช่โดเมน → `ม.ค.` `ก.ย. 2569` `อ.เมือง` `จ.ม.` `ธ.ไทยพาณิชย์` ไม่ถูกตัด) ⑥ IP ⑦ คำที่ NFKC แล้ว (+①–③ อีกรอบ) เป็นลิงก์ (`ⓔⓥⓘⓛ.ⓒⓞⓜ` · `evil︒com`) = ตัดทั้งคำ ·
  เริ่มจับเฉพาะต้นคำ + ตัดลิงก์จากข้อความยาว n+200 ก่อนตัดเหลือ n (โดเมนคร่อมจุดตัดยังถูกจับ) ·
  **ตัดความยาวก่อน `maskPII` เสมอ** (`newsTxt` = n+400 — regex อีเมลช้าแบบกำลังสอง: รีวิวยาว 50,000 ตัวที่คีย์สาธารณะแทรกได้ 3 แถว เคยทำให้สรุปใช้ 30 วิ+)
  ตัวอย่างที่ตัด: `จริงใจหมูกระทะ.com/login` · `jjmoo.онлайн/admin` · `пример.рф/x` · `evil。com` · `ｅｖｉｌ．ｃｏｍ` · `evil<ZWSP>.com` · `aก.com` · ชื่อช่องทาง `ร้าน.com`
- **ค่าแฮชรหัสผ่านใน `pnl_users` คีย์สาธารณะอ่านได้** (ข้อจำกัดของทั้งระบบ — `bossCheck` จึงกันได้แค่คนทั่วไป) → จำกัดความเสียหายด้วยสถานะที่คีย์สาธารณะเขียนไม่ได้:
  ส่งเองวันละ ≤5 ครั้ง + เฉพาะ 7 วันล่าสุด · `content_ai` วันละ ≤6 ครั้ง · เปลี่ยนกลุ่มแล้วแจ้งกลุ่มเดิม (ดูข้างบน/หัวข้อ 11)
- `line-order` เองรับคำขอจากคีย์สาธารณะ (แอปนับสต๊อก/ครัวกลาง/ออฟฟิศเรียกจากเบราว์เซอร์ ส่งกลุ่ม/ข้อความอะไรก็ได้) — การกันในหัวข้อนี้ครอบคลุมเฉพาะทางของ JJ Social
  (ปิดช่องทางนั้นจริงต้องให้ `line-order` ตรวจสิทธิ์/จำกัดกลุ่มปลายทางเอง)
- หัวข้อ ✨ / 👉 ควรทำ ใส่ใน LINE **เฉพาะสรุป AI ที่ทำในรอบเดียวกันในหน่วยความจำ** (`digest_src:"run"` — cron ส่งผลของ `makeSummary` ต่อให้ `makeNews` ตรง ๆ) ·
  ปุ่ม 📤 (สรุปอ่านจาก `social_daily` ที่คีย์สาธารณะแก้ได้ = `"db"`) ไม่ใส่ 2 ส่วนนี้ (ยังโชว์ในแอปตามเดิม)
- ลำดับงาน cron (ไม่เกิน ~115 วิ): สรุป AI (เลย 60 วิ = สาขาที่เหลือใช้สรุปแบบกติกา) → 📰 สรุป + ส่ง LINE → heartbeat → เรียนรู้ FAQ (ถ้าเหลือ >30 วิ) → 📈 วิเคราะห์คลิปรายสัปดาห์

### 11) 📈 วิเคราะห์โพสต์/คลิป — ทำไมแต่ละคลิปได้ยอดไม่เท่ากัน (v2026-10-08.1)

**ต้องรัน `jjmk_social_posts.sql` รุ่นล่าสุด** (เพิ่มคอลัมน์ `shares` · `saves` · `duration` · `hashtags` · `ptype` ใน `social_posts`)
— ยังไม่รัน = ฟังก์ชันอ่าน/เขียนแบบเดิมเอง (ไม่พัง แต่ไม่มียอดแชร์/เซฟ/ความยาว) · ยอดใหม่ได้ตอนดึงรอบถัดไป หรือกด **🔄 อัปเดตยอดทุกโพสต์**
(action `apify_restat` · ผู้ดูแล/เจ้าของ · อ่านรายการโพสต์ทั้งหมดใหม่ทุกแหล่ง FB/IG/TikTok แบบขั้นแรกของ 🚀 · คีย์รอบ `<แหล่ง>~st` · ใช้งบ/เพดานเดียวกับงานอื่น · ไม่แตะสถานะงาน 🚀 ·
กันจ่ายซ้ำสองทาง: 🚀 กำลังอ่านรายการ (`~all`) = ไม่เริ่ม `~st` · `~st` กำลังทำ = 🚀 ยังไม่เริ่ม `~all` (`last[<แหล่ง>~all].wait` = "รอรอบอัปเดตยอดให้เสร็จก่อน" ·
`~st` จบแล้ว = ล้างข้อความนี้ทุกรอบ แม้ `~all` ยังเริ่มไม่ได้เพราะงบ/เพดาน · แอปโชว์เฉพาะตอน `~st` ยังอยู่ใน `runs`))

action **`content_ai`** `{u,h,ch,days}` (ผู้ดูแล/เจ้าของ · `ch` = tiktok/facebook/instagram · `days` = 30/90/0=ทั้งหมด ·
**วันละ ≤6 ครั้ง** — จอง `social_sys` **`content_ai:<วันนี้ไทย>:<n>`** n=1..6 หลัง `bossCheck` + เช็คช่องทาง (กดพร้อมกันก็ไม่เกิน 6 · ครบ = `{ok:false, reason:"สั่งวิเคราะห์ได้วันละไม่เกิน 6 ครั้ง (กันค่าใช้จ่าย) — พรุ่งนี้กดได้อีก"}` ·
ไม่มีตาราง `social_sys` = `{ok:false, reason:<ให้รัน SQL>}` · งานรายสัปดาห์ของ cron ไม่นับ):
โพสต์ ≤300 ล่าสุด (ต้องมียอดวิว/ไลก์ ≥5 โพสต์) → ค่ากลาง · ER · ×ค่ากลาง · สถิติแยกกลุ่ม (วัน · ช่วงเวลา · ความยาวคลิป · ประเภท · แฮชแท็ก · ความยาวคำบรรยาย)
+ คอมเมนต์ต่อโพสต์ (อารมณ์/เรื่องที่พูดถึง/ตัวอย่าง — ไม่มีชื่อผู้คอมเมนต์) + **รูปปก** (เฉพาะรูปใน Storage `social-media` · ≤600KB/รูป · รวม ≤4MB)
→ AI ตามโหมด (Claude ในโหมดคุณภาพสูงสุด → Gemini ฟรี (ส่งพร้อมรูปไม่ผ่าน = ลองข้อความล้วน) → กติกาสถิติล้วน) อธิบายโพสต์เด่น/ไม่ปัง ·
รูปแบบที่เจอ · ควรทำ/ควรเลี่ยง · ไอเดียคลิปถัดไป · **ไอเดียเมนูใหม่จากคอมเมนต์** · เวลาโพสต์ที่ดี → เก็บที่ `social_daily` kind=`content` branch=`<ช่องทาง>`
· cron 06:10 วิเคราะห์ให้เอง**สัปดาห์ละครั้งต่อช่องทาง วันละไม่เกิน 1 ช่องทาง** (ช่องทางที่วิเคราะห์ล่าสุดนานที่สุด) —
**จองวันก่อน** = insert `social_sys` **`content_run:<วันนี้>`** `{ch,at,ok}` (ซ้ำ = ข้าม · ไม่มีตาราง = ไม่วิเคราะห์ — ลบแถว `social_daily` ทิ้งแล้วเรียก summary รัว ๆ ก็ไม่วิเคราะห์ซ้ำ) ·
การจองนี้**เป็นตัวกันวันละครั้งตัวเดียว** — ไม่ดูว่า "วันนี้มีแถว content แล้ว" (เดิม `done_today` · `social_daily` คีย์สาธารณะเพิ่มแถวได้ เคยทำให้ข้ามทุกวัน) ·
**"วิเคราะห์ล่าสุด" ของแต่ละช่องทางอ่านจาก `social_sys` เท่านั้น** = การจอง `content_run:<วัน>` (cron) + `content_ai:<วัน>:<n>` (ปุ่ม — จด `{ch,ok}` หลังวิเคราะห์) ที่ `ok:true` ·
ไม่อ่าน `social_daily` (แถว content ปลอมครบ 3 ช่องทางเคยทำให้ "ยังไม่ถึงรอบ" ไปตลอด) · ช่องทางที่วิเคราะห์สำเร็จใน 7 วัน แค่ยังไม่ถึงรอบ ช่องทางอื่นยังทำได้ ·
ช่องทางที่มีสิทธิ์ = มีโพสต์ที่มียอดวิว/ไลก์ ≥5 **ใน 90 วัน** (ช่วงเดียวกับที่วิเคราะห์จริง — เดิมนับทั้งหมด ช่องทางที่เลิกโพสต์ไปแล้วถูกเลือกทุกวันแต่วิเคราะห์ไม่ได้ ช่องทางอื่นไม่เคยได้ทำ) ·
ช่องทางแรกไม่ผ่านเร็ว ๆ + เหลือเวลา ≥60 วิ = ลองช่องทางถัดไป (ผลวิเคราะห์ยังวันละ ≤1 · ไม่เก็บแถว "ข้าม") · เหลือเวลาไม่ถึง 50 วิ = ข้ามวันนี้ (ไม่จองวัน) ·
Gemini (รวมรอบลองแบบข้อความล้วน) เริ่มเฉพาะเมื่อเหลือเวลา ≥45 วิ ไม่งั้นใช้สถิติล้วน
· AI ดูคลิปไม่ได้ — เห็นแค่คำบรรยาย รูปปก เวลา ความยาว ประเภท แฮชแท็ก ยอด และคอมเมนต์ (ผลบอกไว้ใน caveats)
