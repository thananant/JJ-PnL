สำหรับเจ้าของร้านและช่างติดตั้ง ทำตามลำดับข้อ 0 → 6 **ห้ามสลับลำดับข้อ 1 กับข้อ 2** · เขียนจากโค้ด ณ 2026-10-19

> **ตัวย่อที่ใช้อ้างอิง**: `worker.js` = `jjmk-payroll/worker.js` · `payroll.html` = `jjmk-payroll.html` ·
> `P-CLAUDE` = `jjmk-payroll/CLAUDE.md` · `kpi.sql` = `jjmk-kpi.sql` ใน branch `sql`

## สรุปสั้น ๆ ก่อนอ่าน

1. เครื่องใหม่ต้องชี้มาที่ **Worker ตัวเดิม** `steep-hill-7d52.thananantpatt.workers.dev` ไม่ต้องสร้าง Worker ใหม่ ไม่ต้องแก้โค้ด ถ้าเครื่องเป็น ZKTeco หรือ Hikvision (P-CLAUDE:13 · MOVE-CHECKLIST.md:33)
2. **ลงหน้าและลองสแกนให้เสร็จก่อนชี้เครื่องมาที่ Worker** พอชี้แล้ว ทุกสแกนที่ผ่านจะเป็นเวลาเข้างานจริงที่ใช้คิดเงินทันที รวมถึงการลองสแกนตอนลงหน้า (ข้อ 1 → ข้อ 2)
3. **รหัสพนักงานในเครื่องใหม่ต้องตรงกับรหัสเดิมทุกตัวอักษร** ถ้าไม่ตรง ระบบจะสร้างพนักงานซ้ำ หรือเวลาไปลงที่คนอื่น และเงินเดือนจะผิด (ข้อ 1)
4. **ผูกเครื่องกับสาขาในตาราง `devices`** แอปไม่มีปุ่มให้ทำ ต้องทำใน Supabase (ข้อ 3)
5. **นาฬิกาเครื่องต้องเป็นเวลาไทยที่ตรง** ระบบบันทึกเวลาตามที่เครื่องส่งมา ไม่มีขั้นไหนช่วยแก้ให้
6. **ทดสอบด้วยเวลาเข้า-ออกงานจริง แล้วดูว่าชื่อขึ้นในแอป** การที่เครื่องขึ้นว่า "ส่งสำเร็จ" ยังไม่พอ เพราะ Worker ตอบ OK เสมอ (worker.js:152-155, 742-748, 812-819)

## 0. ต้องรู้ก่อนเริ่ม (ก่อนซื้อหรือก่อนนัดช่าง)

| เรื่อง | ทำไมต้องรู้ |
|---|---|
| **ยี่ห้อ/รุ่น** | Worker รับได้ 2 แบบเท่านั้น: **ZKTeco** ที่ใช้ ADMS/iclock ("Cloud Server") และ **Hikvision** ที่ใช้ ISAPI "HTTP Listening" (worker.js:7-11) · ยี่ห้ออื่นหรือโปรโตคอลอื่น Worker จะตอบ `OK` แต่ไม่บันทึกอะไร (worker.js:151) ต้องแก้ worker.js แล้ว deploy ใหม่ก่อน **แจ้ง Claude ก่อนซื้อ** |
| **ช่องปลายทางรับ "ชื่อโดเมน" ได้ไหม** (ทั้ง 2 ยี่ห้อ) | Worker อยู่บน `*.workers.dev` ไม่มี IP คงที่ ตั้งได้แค่ชื่อโดเมน (worker.js:135, 139) · เฟิร์มแวร์ที่ช่อง Server / HTTP Listening รับได้แค่ตัวเลข IPv4 ใช้กับ Worker นี้ไม่ได้ |
| ZKTeco: ใส่โดเมนกับพอร์ต 443 ได้ไหม | Worker ฟังแค่ path `/cdata` `/getrequest` `/devicecmd` (worker.js:77-92) · รุ่นที่ใช้ PUSH แบบใหม่ซึ่งส่งไป path อื่น ยังไม่เคยทดสอบกับระบบนี้ |
| **ZKTeco: รองรับ HTTPS/SSL ไหม** | พอร์ต 443 ของ workers.dev ต้องคุยแบบ HTTPS · หน้า Worker บอกแค่ Address/Port (worker.js:131-136) เพราะรุ่นเดิมคุย HTTPS ได้ · ZK บางรุ่นต้องเปิดสวิตช์ HTTPS แยก บางรุ่นทำ HTTPS ไม่ได้เลย ใส่ 443 ได้แต่ส่งข้อมูลไม่ถึง · **ไม่รองรับ HTTPS = หยุด แล้วแจ้งเจ้าของ** (แบบเดียวกับ Hikvision แถวถัดไป) |
| Hikvision: เลือก **HTTPS** ใน HTTP Listening ได้ไหม | หน้า Worker เขียนว่า "ถ้าไม่มี HTTPS ให้ดูแผนสำรองในคู่มือ" (worker.js:142) **แต่ไม่มีแผนสำรองนี้เขียนไว้ที่ไหนเลย** ถ้าเลือก HTTPS ไม่ได้ ต้องหาทางแก้ก่อนติดตั้ง |
| Hikvision: เลือกรูปแบบข้อมูลเป็น **JSON** ได้ไหม | Worker อ่านได้แค่ JSON (หาเครื่องหมาย `{` ตัวแรก ไม่เจอก็ทิ้ง worker.js:718-719, 752-754) · ถ้าเครื่องส่งเป็น XML ทุกสแกนจะหายเงียบ ๆ ต้องแก้ Worker ก่อน |
| **ล้างบันทึกการเข้างานในเครื่องได้ โดยไม่ลบผู้ใช้/ใบหน้า ไหม** | ต้องใช้ในข้อ 2 (ล้างสแกนลองก่อนชี้มาที่ Worker) และข้อ 6 |
| **ไว้ที่ไหน** | ใช้กำหนดค่า `branch`: `JJLP` / `JJRD` (ร้านเดิม เครื่องที่ 2) · `JJCK` (ครัวกลาง) · `OFFICE` · สาขาใหม่ต้องแก้แอปก่อน (ข้อ 3) |
| **เน็ตที่จุดติดตั้ง** | เครื่องต้องออก HTTPS พอร์ต 443 ไปหาโดเมน Worker ได้ · ต้องตั้ง **Gateway และ DNS** ได้ (เพราะใส่เป็นชื่อโดเมน) · แนะนำ IP คงที่ (เหตุผลอยู่ในข้อ 1) |
| **SN ของเครื่อง** | จะใช้เป็นค่า `devices.sn` ตอนผูกสาขา · ZKTeco = Serial Number ที่เครื่องส่งมาใน `?SN=` (worker.js:52) · Hikvision = `deviceID` ถ้าไม่มีใช้ `macAddress` ถ้าไม่มีใช้ `ipAddress` ถ้าไม่มีอีกใช้คำว่า `HIK` (worker.js:730) **อาจไม่ใช่เลขบนสติกเกอร์** รู้แน่หลังมีคนสแกนครั้งแรก |

## 1. ตั้งเครื่อง + ลงหน้าพนักงาน (ตอนเครื่อง**ยังไม่ได้**ชี้มาที่ Worker)

**ทำข้อนี้ให้เสร็จทั้งหมดก่อนข้อ 2** ระหว่างนี้ช่องปลายทางยังว่าง (ZK: ยังไม่ใส่ Server Address · Hikvision: ยังไม่เปิด HTTP Listening) หรือถอดสาย LAN ไว้ก็ได้ จะลองสแกนกี่ครั้งก็ไม่เข้าระบบเงินเดือน

> **ทำไม**: พอเครื่องชี้มาที่ Worker แล้ว ทุกสแกนที่ผ่านเป็นเวลาเข้างานจริงของรหัสนั้น ZK บันทึกทุกบรรทัด ATTLOG (worker.js:85, 797-819) Hikvision บันทึกทุกเหตุการณ์ที่มีรหัส (worker.js:717-748) กันซ้ำได้แค่สแกนในนาทีเดียวกัน ถ้าพนักงานลองสแกนหลังลงหน้า:
> - วันที่มีสแกนนับเป็นวันทำงาน `days = ss.length` (payroll.html:3109) คนรายวันได้ค่าแรงเพิ่ม `days * rate` (payroll.html:3228) และวันนั้นไม่ถูกนับว่าหยุดวันห้ามหยุด (payroll.html:3195)
> - สแกนครั้งเดียวในวันที่ไม่ได้ทำงาน = ปรับลืมตอก 200 (payroll.html:3215 · P-CLAUDE:49)
> - สแกน 2 ครั้งห่างกันนอกเวลากะ = กลายเป็นคู่เข้า-ออก แล้วคิดสาย/ออกก่อนหลายร้อยนาที × 1.5 บาท (payroll.html:3025-3037, 3213 · P-CLAUDE:48)
> - ลองสแกนก่อนเข้ากะจริง: ระบบใช้สแกนแรก/สุดท้ายเลือกกะ (payroll.html:2925-2933 · worker.js:258-273) จึงจับกะ สาย และออกก่อนผิดได้ · Parttime นับ in = สแกนแรก out = สแกนสุดท้าย (payroll.html:2989-2992)
> - จอลูกค้า KPI นับคนที่ยังอยู่จากจำนวนสแกนคี่ (kpi.sql:278-290) สแกนเกิน 1 ครั้ง ชื่อจะหายหรือค้างผิดทั้งกะ · รายงาน LINE 11:01/15:01/18:01/21:00 นับว่าเข้างานแล้ว (worker.js:449-457, 507-513) · เช้าวันรุ่งขึ้นออฟฟิศ AI ขึ้นแดง "สแกนครั้งเดียว" (jjmk-office.html:674-690)

### 1.1 ตั้งเครือข่ายและเวลา

| เมนูบนเครื่อง | ค่าที่ต้องใส่ |
|---|---|
| IP address | IP คงที่ ที่ไม่ซ้ำกับเครื่องอื่นในร้าน (ถ้าเป็น Hikvision ให้ไม่ซ้ำกับ Hikvision ทุกเครื่องทุกสาขาด้วย ดูข้อ 2B) |
| Gateway | IP ของเราเตอร์ |
| **DNS** | `1.1.1.1` / `8.8.8.8` หรือ IP ของเราเตอร์ · **ห้ามเว้นว่าง** ช่องนี้มักว่างหลังเปลี่ยนเป็น IP คงที่ เครื่องจะหาโดเมน Worker ไม่เจอ ไม่ส่งอะไรเลย ตาราง `devices`/`device_log` ก็ไม่มีแถว และ NTP ก็ใช้ไม่ได้ |
| วันที่/เวลา | เขตเวลา **GMT+7 / (GMT+07:00) Bangkok** + นาฬิกาตรงกับเวลาจริง (เปิด NTP / ซิงก์เวลาอัตโนมัติถ้ามี) |

- **เขตเวลาสำคัญมาก (Hikvision)**: Worker แปลงเวลาให้เฉพาะเวลาที่ลงท้ายด้วย `Z` ส่วนเวลาที่มี offset อื่นจะใช้ตัวเลขตามที่เครื่องเขียนมาเลย ถ้าเครื่องตั้งเป็น `+00:00` เวลาจะคลาด 7 ชม. ถ้าตั้งเป็น `+08:00` จะคลาด 1 ชม. และไม่มีอะไรเตือน (worker.js:771-781)

### 1.2 ลงหน้าพนักงาน

## 3. ผูกเครื่องกับสาขา

**วิธีที่ถูก**: ใส่ค่า `branch` ในตาราง `devices` เป็น **รหัสสาขา** `JJLP` / `JJRD` / `JJCK` / `OFFICE` เท่านั้น ห้ามใช้ชื่อไทย
- แอปเงินเดือนรู้สาขาของเครื่องจากตาราง `devices` อย่างเดียว (payroll.html:2481, 2537) และไม่มีหน้าจอให้แก้ ต้องทำใน Supabase
- **อย่าใช้ secret `BRANCH_MAP` แทน**: มีผลแค่กับรายงาน LINE แอปไม่ได้อ่าน (worker.js:219-225) · ตัวอย่างในคอมเมนต์ใช้ชื่อไทย (`GG1207018=ลาดพร้าว`) ซึ่งผิด เพราะโค้ดเทียบด้วยรหัส (worker.js:30-32 เทียบกับ 192, 296-297) · ถ้าตั้ง `BRANCH_MAP` ไว้แล้ว ค่าใน `BRANCH_MAP` ของเครื่องเดียวกันต้องตรงกับใน `devices` เพราะ `BRANCH_MAP` จะทับค่าในตาราง

### SQL ผูกสาขา (แก้ข้อมูลจริง 1 แถว ไม่ลบอะไร รันซ้ำได้)

```sql
-- ผูกเครื่องใหม่กับสาขา: แก้เฉพาะแถวของ SN นี้
update devices
   set branch = 'JJRD',                  -- JJLP / JJRD / JJCK / OFFICE เท่านั้น
       name   = 'รัชดา เครื่องที่ 2'       -- ชื่อเรียก (ไม่บังคับ)
 where sn = 'ใส่ SN ของเครื่องใหม่ตรงนี้'
returning sn, branch, name, last_seen;
```

- ได้ **0 แถว** = SN ผิด หรือเครื่องยังไม่เคยต่อเข้ามา (Hikvision: ยังไม่มีใครสแกนสำเร็จ) ให้ไปหา SN จริงในข้อ 4 ก่อน
- **ถ้า SN เป็น `HIK` ห้ามผูกสาขา** (เครื่องไม่ส่งทั้ง deviceID/MAC/IP ถ้ามี Hikvision เครื่องอื่นตกมาเป็น `HIK` ด้วยจะปนกัน) ให้แจ้ง Claude
- ค่าที่ผูกไว้จะไม่หาย เพราะเวลาเครื่องรายงานตัว Worker อัปเดตแค่ `sn` กับ `last_seen` (worker.js:862-869)
- **ผูกเสร็จแล้วต้องรีเฟรชแอปเงินเดือน** (กด 🔄 หรือโหลดหน้าใหม่) เพราะแอปอ่าน `devices` ตอนเปิดเท่านั้น (payroll.html:2481, 7269-7305) · สแกนย้อนหลังจะถูกจัดสาขาใหม่ให้เอง
- สาขาของเครื่องใช้แค่บอก "ทำงานที่สาขาไหน / ข้ามสาขา" ในรายงาน **ไม่มีผลกับยอดเงิน** (payroll.html:3202-3204, 5827, 6737)

## 4. ทดสอบ (ทำทันทีหลังติดตั้ง)

**ทดสอบด้วยเวลาเข้า-ออกงานจริงเท่านั้น ไม่ต้องสแกนเพิ่ม** สแกนทดสอบเป็นข้อมูลจริงที่ใช้คิดเงิน (เหตุผลในข้อ 1)

1. **(ZKTeco) เช็คว่าต่อติดก่อนสแกน**: รัน SQL ข้อ 0 ข้อ 3 ต้องเห็น SN เครื่องใหม่ และ "ผ่านมาแล้ว" ไม่กี่นาที (ค่า `last_seen` ดิบเป็น UTC ช้ากว่าเวลาไทย 7 ชม.)
2. **รอคนที่กำลังจะเข้ากะ** (ลงหน้าแล้ว รหัสตรง · ไม่ใช่ Parttime · ไม่ใช่วันหยุดของเขา) ให้สแกน**เข้างานจริง** 1 ครั้ง จดชื่อและเวลาไว้
3. **เปิด** `https://steep-hill-7d52.thananantpatt.workers.dev/report/check` ดูหัวข้อ "เครื่องสแกน -> สาขา" ต้องเห็น SN เครื่องใหม่พร้อมจำนวนครั้ง (worker.js:584-589)
   - ขึ้น "⚠️ ยังไม่ผูกสาขา!" = จด SN นี้ไว้ แล้วทำ SQL ข้อ 3 (สำหรับ Hikvision นี่คือ SN จริงที่ต้องใช้)
4. **ดูเวลาที่บันทึก** (อ่านอย่างเดียว) ต้องตรงกับเวลาที่จดไว้ วันที่ต้องถูก:

```sql
-- สแกนล่าสุดของเครื่องใหม่ (อ่านอย่างเดียว)
select emp_code, punch_date, punch_time, verify_mode, source
  from punches
 where device_sn = 'ใส่ SN ของเครื่องใหม่ตรงนี้'
 order by punch_date desc, punch_time desc
 limit 20;
```

5. **เช็คว่าไม่มีพนักงานเกิดใหม่โดยไม่ตั้งใจ** (อ่านอย่างเดียว · เปลี่ยน `0` เป็น id ที่จดไว้ในข้อ 0 ข้อ 6):

```sql
-- พนักงานที่เกิดหลังวันติดตั้ง (อ่านอย่างเดียว)
-- ถ้าขึ้น error ว่าไม่มีคอลัมน์ start_date ให้ลบ "start_date," ออก
select id, code, nick, full_name, branch, start_date,
       case when nick = code then '⚠️ ระบบสร้างเอง (รหัสในเครื่องไม่ตรง?)' end as "เตือน"
  from employees
 where id > 0
 order by id desc;
```

6. **(Hikvision) ดูข้อมูลดิบ**: Supabase → Table Editor → ตาราง `device_log` → กรอง `path` = `/hik` → เรียงจากใหม่ไปเก่า ดูช่อง `body` (worker.js:63-64, 871-878)
   - **มี `deviceID` หรือ `macAddress` ไหม** ถ้าไม่มี ระบบจะใช้ IP ในวง LAN เป็นรหัสเครื่อง → IP ต้องไม่ซ้ำกับ Hikvision เครื่องอื่น (ข้อ 2B) · ถ้า SN ออกมาเป็น `HIK` ห้ามผูกสาขา แจ้ง Claude
   - ขึ้นต้นด้วย `{` หรือมี JSON อยู่ข้างใน (ถ้าขึ้นต้นด้วย `<?xml` / `<EventNotificationAlert` = เครื่องส่ง XML ดูข้อ 5)
   - `dateTime` ลงท้ายด้วย `+07:00` ไหม
   - สแกน 1 ครั้งได้กี่แถว (ควรได้ 1 แถว)
   - ช่อง `sn` ของแถว Hikvision จะว่าง เป็นปกติ (Worker จด sn จาก `?SN=` ซึ่ง Hikvision ไม่ส่งมา)
7. **ผูกสาขา (ข้อ 3) แล้วรีเฟรชแอปเงินเดือน** → หน้าวันนี้ ชื่อคนนั้นต้องขึ้นว่าเข้าแล้ว ในการ์ดของสาขาที่ถูก (สแกนใหม่ขึ้นเองแบบ realtime payroll.html:7272-7280)
8. **ตอนคนเดิมสแกนออกงานจริง** (สิ้นกะ) ต้องเห็นเวลาออก

| ดูที่ | ผลที่ควรเห็น |
|---|---|
| `devices` | มีแถว SN ใหม่ · `branch` เป็นรหัสสาขา · (ZK) "ผ่านมาแล้ว" ไม่กี่นาที |
| `/report/check` | SN ใหม่ + จำนวนครั้ง + ชื่อสาขา ไม่มี ⚠️ |
| `punches` | วันที่/เวลาตรงกับที่สแกนจริง · `source` = `device` |
| `employees` | SQL ขั้น 5 ไม่มีแถวที่ไม่ได้ตั้งใจเพิ่ม |
| แอป หน้าวันนี้ | ชื่อขึ้นในการ์ดสาขาที่ถูก ไม่มีป้ายข้ามสาขาแปลก ๆ |

> **หน้า `/debug` ไม่ได้ตรวจเครื่องสแกน** มันเช็คแค่ secret กับฐานข้อมูล และจะเขียนแถว `sn = 'DEBUG-TEST'` ทิ้งไว้ในตาราง `devices` (worker.js:880-931) ใช้ได้แค่ตอนสงสัยว่า Worker หรือฐานข้อมูลเสีย

### ถ้ามีสแกนทดสอบเกิน (ช่างหรือพนักงานลองสแกนหลังชี้มาที่ Worker)

1. จดชื่อ + วัน + เวลาของสแกนที่ไม่ใช่เวลาทำงานจริงทุกครั้ง
2. **หลังคนนั้นสแกนออกงานจริงของวันนั้นแล้ว** (หรือเช้าวันรุ่งขึ้น) และก่อนปิดงวด: แอปเงินเดือน → ข้อมูลพนักงาน → คนนั้น → แท็บเวลาทำงาน → ✎ ของวันนั้น (payroll.html:5269)
   - วันที่เขาทำงานจริง: ใส่เวลาเข้า-ออกจริง แล้วกดบันทึก · การบันทึกจะ**ลบสแกนทั้งวันกะนั้น**แล้วเขียนแค่เวลาเข้า-ออกที่ใส่ (payroll.html:4651-4661, 4676-4699) สแกนทดสอบจึงหายไปด้วย · เวลาที่แก้มือไม่มี SN เครื่อง วันนั้นจึงจับข้ามสาขาไม่ได้
   - วันที่เขาไม่ได้ทำงาน: กด 🗑 ลบเวลาทั้งวันนี้ (payroll.html:2006, 4706-4717) · ปุ่มนี้ลบทั้งวันกะ ถ้าวันนั้นมีเวลาจริงอยู่ด้วยให้ใช้วิธีบนแทน
3. อย่าแก้ระหว่างที่คนนั้นยังทำงานอยู่ สแกนออกจริงที่เข้ามาทีหลังจะต่อท้ายเวลาที่แก้ไว้

### ช่องทางสำรอง: นำเข้าไฟล์ .xlsx จากเครื่อง (ใช้ด้วยความระวัง)

ใช้ได้เฉพาะเมื่อเครื่องต่อเน็ตไม่ได้ช่วงแรก และ**ไฟล์ที่เครื่อง export มามีหัวคอลัมน์ตรงอยู่แล้ว** หน้าตั้งค่าของแอป → นำเข้าไฟล์การเข้างาน (payroll.html:1115-1124, 2804-2870)

- **หัวคอลัมน์ต้องตรงตัวอักษร**: `First Name` · `Last Name` · `ID` · `Department` · `Date` · `Time` (หาแถวหัวจาก `First Name` + `Date` แล้วหาคอลัมน์อื่นด้วยชื่อตรงตัว payroll.html:2810-2813) · เครื่องยี่ห้อหรือรุ่นใหม่มักไม่ตรง → **ส่งไฟล์ตัวอย่างให้ Claude ตรวจก่อน ห้ามแก้หัวคอลัมน์เองให้ผ่าน**
- **ก่อนนำเข้า ลบค่าในคอลัมน์ `Department` ทิ้งให้ว่างทั้งคอลัมน์** (เก็บหัวคอลัมน์ไว้): ตัวนำเข้าจะ**เขียนทับแผนกของพนักงานทุกคนในไฟล์**ถ้าค่าไม่ตรงของเดิม (payroll.html:2854-2868) และตามคอมเมนต์ในโค้ด (2854) กับตัวเลือก "อัตโนมัติตามแผนก" ในฟอร์ม (1750) ฐานข้อมูลอาจเติมสาขาตามแผนกให้ด้วย (ไม่พบ SQL ของ trigger นี้ใน branch `sql` จึงยืนยันจากโค้ดไม่ได้) · แผนกมีผลกับเงิน: ยกเว้นกฎห้ามหยุด (payroll.html:3179-3181) · จับกะเฉพาะแผนก เช่น กะล้างจาน (payroll.html:2435-2441 · worker.js:244-256) · เพดานเบิกของ Manager (payroll.html:3258-3259) · เครื่องใหม่ไม่ได้ตั้งแผนกแบบเดียวกับ payroll
- **วันที่ต้องเป็น วัน/เดือน/ปี ค.ศ.** (รับแค่ `D/M/YYYY` หรือ `YYYY-M-D` payroll.html:2909-2915) · ถ้าไฟล์เป็น เดือน/วัน/ปี วันที่ ≤ 12 จะสลับวันกับเดือน**โดยไม่เตือน** · ถ้าเป็นปี พ.ศ. จะได้ปีผิด
- `ID` ต้องตรงรหัสเดิม · รหัสที่ไม่รู้จักจะถูกสร้างเป็นพนักงานรายเดือน 12,000 (payroll.html:2833-2838) · **ห้ามนำเข้าไฟล์ที่มีรหัสทดสอบหรือสแกนทดสอบ**
- สแกนที่นำเข้าจะไม่มีสาขาของเครื่อง

```sql
-- สแกนของเครื่องใหม่แยกคน (อ่านอย่างเดียว)
select p.emp_code         as "รหัส",
       e.nick             as "ชื่อเล่น",

 group by p.emp_code, e.nick, e.full_name, e.branch

```

### กติกาการสแกนถ้ามี 2 เครื่องที่เดียวกัน

**สแกนเครื่องเดียวต่อครั้ง** จอลูกค้า (KPI) นับว่าใครยังอยู่ในร้านจากจำนวนสแกนในวัน เลขคี่ = ยังอยู่ (kpi.sql:278-290) ถ้าตอนเข้าสแกนทั้ง 2 เครื่อง (คนละนาที) จะกลายเป็นเลขคู่ แล้วจอลูกค้าจะซ่อนชื่อคนที่ยังทำงานอยู่ · สแกนในนาทีเดียวกันไม่เป็นไร ระบบนับเป็นครั้งเดียว (worker.js:808, 814-818)

### รับพนักงานใหม่หลังมี 2 เครื่อง

คู่มือ PDF หน้า 10 ข้อ 4.1 ให้ลงหน้าที่เครื่องแล้วให้ระบบสร้างพนักงานให้ตอนสแกนครั้งแรก (worker.js:830-831) แต่พอมี 2 เครื่อง แต่ละเครื่องเสนอ User ID ถัดไปของตัวเองแยกกัน พนักงานใหม่ 2 คนที่ลงคนละเครื่องอาจได้รหัสเดียวกัน แล้วเวลาของคนที่ 2 ไปรวมกับคนแรกเงียบ ๆ (worker.js:825-828) จึงให้ทำแบบนี้แทน:

1. **ออกรหัสจากที่เดียว**: เพิ่มคนในแอปพร้อมรหัสก่อน (หน้าพนักงาน → ＋ เพิ่ม → ช่อง "รหัสพนักงาน (จากเครื่องสแกน)" payroll.html:1727) แล้วเช็คว่ายังไม่มีใครใช้:

```sql
-- ต้องได้ 0 แถว ทั้ง 2 คำสั่ง (อ่านอย่างเดียว)
select code, nick, active from employees where code = 'ใส่รหัสใหม่ตรงนี้';
select count(*) as "สแกนค้างของรหัสนี้" from punches where emp_code = 'ใส่รหัสใหม่ตรงนี้';
```

2. **ใส่รหัสเดียวกันในทุกเครื่องที่คนนั้นจะใช้** ห้ามใช้ ID ที่เครื่องเสนอให้
3. ลองสแกนหลังลงหน้า = เวลาจริง (ข้อ 2 "ถ้าต้องลงหน้าคนเพิ่ม") ให้ลงหน้าตอนเขาจะเข้ากะ แล้วใช้สแกนนั้นเป็นเวลาเข้างาน
4. ถ้าใช้วิธีนี้ต่อ ให้ Claude แก้คู่มือ PDF ข้อ 4.1 ให้ตรง

### ถ้าเจอพนักงานถูกสร้างซ้ำ หรือเวลาไปลงผิดคน

- **ห้ามกด 🗑 ลบพนักงาน** เพราะจะลบเวลาสแกนทั้งหมดของรหัสนั้นทิ้งถาวร (payroll.html:4633-4640)
- **ห้ามแก้รหัสในฟอร์ม ✎ เพื่อรวมคน** เพราะแก้แค่ `employees.code` เวลาสแกนเดิมไม่ย้ายตาม (payroll.html:4564, 4615-4618) · ยกเว้นคนที่ยังไม่เคยมีสแกนเลย (ข้อ 0 ข้อ 5)
- ลำดับแก้:
  1. แก้รหัสในเครื่องให้ตรง
  2. ให้ Claude เตรียม SQL ย้ายเวลาสแกนจากรหัสที่ผิดไปรหัสที่ถูก เป็นการแก้ข้อมูลจริง **เจ้าของต้องอนุมัติก่อน** (CLAUDE.md:10) แล้วค่อยจัดการแถวที่ซ้ำ
  3. **ZK: เช็คว่าเวลาสแกนเข้า `punches` ครบแล้ว แล้วลบบันทึกการเข้างานในเครื่องด้วย** ก่อนหรือพร้อมกับการย้าย/ลบในฐานข้อมูล · Worker ตอบ `Stamp=9999` คงที่ (worker.js:42, 78-81) เครื่องบางรุ่นอาจส่งประวัติในเครื่องขึ้นมาใหม่ตอนเริ่มเครื่องหรือต่อใหม่ (ขึ้นกับรุ่น ยังไม่ได้ทดสอบ) แถวที่ลบไปจะกลับมา และพนักงานซ้ำจะถูกสร้างใหม่ (worker.js:823-859)
  4. หลังแก้ `punches` ด้วย SQL ให้ทุกเครื่องที่เปิดแอปเงินเดือนกด 🔄 (ข้อ 5 แถวสุดท้าย)
- ถ้าเป็นรหัสทดสอบของช่างล้วน ๆ (ไม่มีใครใช้รหัสนั้นจริง) ปุ่ม 🗑 ลบได้ แต่ถามเจ้าของก่อนกด และลบผู้ใช้นั้นในเครื่อง + ล้างบันทึกการเข้างาน (ZK) ก่อน ไม่งั้นอาจถูกสร้างกลับมา

### ระยะยาว: ขนาดตาราง `device_log`

Worker จดทุกคำขอลง `device_log` (worker.js:64, 871-878) รวม `/getrequest` ที่ ZK ถามทุก 30 วินาที (`Delay=30` worker.js:42) ≈ 2,880 แถว/วัน/เครื่อง ช่อง body เก็บได้ถึง 4,000 ตัวอักษร และ `TransFlag=1111000000` อาจทำให้เครื่องส่งรูปสแกนมาด้วย · ใน repo ไม่มีงานลบ log เก่า เพิ่ม ZK อีกเครื่อง = ตารางโตเร็วขึ้นเท่าตัว · เช็คเดือนละครั้ง (อ่านอย่างเดียว):

```sql
select count(*) as "จำนวนแถว",
       pg_size_pretty(pg_total_relation_size('public.device_log')) as "ขนาด"
  from device_log;
```

ถ้าจะลบ log เก่า **ต้องถามเจ้าของก่อน** (ลบข้อมูลจริง)

## คำถามที่ต้องตอบก่อนเริ่ม

1. **ยี่ห้อ/รุ่นอะไร?** ทั้ง 2 ยี่ห้อ: ช่องปลายทางรับชื่อโดเมนได้ไหม · ตั้ง Gateway/DNS ได้ไหม · ZKTeco: ตั้ง Cloud Server/ADMS แบบโดเมน + พอร์ต 443 ได้ไหม และ**รองรับ HTTPS/SSL ไหม** · Hikvision: เลือก HTTPS ใน HTTP Listening ได้ไหม และ**ส่งเป็น JSON ได้ไหม** · ยี่ห้ออื่น = ต้องแก้ Worker ก่อน
2. **จะไว้ที่ไหน** (เครื่องที่ 2 ของ JJLP/JJRD · ครัวกลาง · ออฟฟิศ · สาขาใหม่) และคนสังกัดอื่น (เช่น OFFICE, JJLP) จะมาสแกนเครื่องนี้ด้วยไหม
3. **ย้ายใบหน้า+รหัสจากเครื่องเดิมได้ไหม** หรือต้องลงใหม่ทีละคน · เครื่องรับรหัสยาว 10 หลักได้ไหม · **ล้างบันทึกการเข้างานโดยไม่ลบผู้ใช้ได้ไหม** · export รายชื่อผู้ใช้ (ID+ชื่อ) ได้ไหม
4. **Worker ใน Cloudflare เป็นรุ่นเดียวกับ `worker.js` ใน repo ไหม** (ข้อ 0 ข้อ 2 — บังคับ) และตั้ง secret `BRANCH_MAP` ไว้หรือเปล่า (ถ้าตั้ง ค่าเป็นอะไร)
5. ถ้าไว้ที่เดียวกับเครื่องเดิม **จะให้พนักงานสแกนเครื่องไหน** (กันจอลูกค้าซ่อนชื่อคนที่ยังทำงานอยู่)
6. **ช่างลงหน้าวันไหน** — ต้องลงหน้าให้เสร็จก่อนชี้เครื่องมาที่ Worker (ข้อ 1 → 2)
