## ระบบทำอะไรได้

- **ฟีดเสียงลูกค้าเรียลไทม์**: LINE OA, Facebook (แชท+คอมเมนต์), Instagram, Google Maps และช่องทางอื่น (Wongnai/Grab/LINE MAN/TikTok — เพิ่มเองหรือยิงผ่าน Generic Webhook)
- **AI วิเคราะห์ทุกรีวิวอัตโนมัติ**: อารมณ์ ชม/ตำหนิ, คะแนน 0-100, แยกประเด็น, จับชื่อพนักงาน, ช่วงเวลาที่มา, ร่างคำตอบ
- **สรุปอัตโนมัติรายวัน 06:10**: มีปัญหาอะไร ใครทำดี ช่วงเวลาไหนดี ควรทำอะไรต่อ
- **แชทบอท** LINE / Messenger / IG DM — ต่อช่องทาง: ปิด / ร่างให้คนตรวจ / ตอบเองเฉพาะคำถามพบบ่อย (FAQ) / ตอบเองทั้งหมด
  ระบบเรียนรู้คำถามที่ลูกค้าถามซ้ำแล้วเสนอเป็น FAQ ให้กดอนุมัติ · ถ้าโควต้า AI หมด บอทยังตอบคำถามที่ตรง FAQ ได้ (เทียบคำแบบไม่ใช้ AI)
- ล็อกอินด้วยบัญชี `pnl_users` เดียวกับ P&L (เข้าจากหน้ารวมระบบได้เลย)

## ขั้นตอนติดตั้ง (ทำครั้งเดียว)

### 1) ฐานข้อมูล
รัน `jjmk_social_setup.sql` แล้วตามด้วย `jjmk_social_fix_grants.sql` ใน Supabase → SQL Editor
· ใช้ปุ่ม 🚀 ดึงย้อนหลังทั้งหมด = รัน `jjmk_social_posts.sql` เพิ่ม (อยู่ branch `sql` — ไฟล์ SQL ใหม่ไม่เก็บใน branch งาน)

### 2) Edge Functions (2 ตัว) — ทำผ่านเว็บ
Supabase Dashboard → **Edge Functions → Deploy a new function (via Editor)**
- ชื่อ `social-brain` → วางโค้ด (ปุ่ม 📋 ในแอป หรือไฟล์ `supabase/functions/social-brain.ts`) → Deploy
- ชื่อ `social-webhook` → วางโค้ด `social-webhook.ts` → Deploy → เข้า Details → **ปิด Verify JWT** (จำเป็น — LINE/Facebook/Google ยิงเข้ามาตรง ๆ)
- แก้โค้ดครั้งถัดไป: เปิดฟังก์ชันเดิม → วางทับ → Deploy (การ์ดสถานะในแอปจะบอกถ้าเวอร์ชันยังเก่า)

### 4) งานอัตโนมัติ (pg_cron) — **สำคัญ ไม่ทำ = ไม่ดึง/ไม่วิเคราะห์/ไม่สรุปเอง**
รัน `jjmk_social_cron.sql` ใน SQL Editor — **ไม่ต้องแก้อะไร** (ใช้คีย์สาธารณะชุดเดียวกับแอป ไม่ใช่คีย์ลับ)

- ทุกวัน 06:10: สรุปเมื่อวาน + เรียนรู้คำถามซ้ำ
- ตรวจว่าทำงาน: การ์ดสถานะในแอปมีแถว "งานอัตโนมัติ (cron)" บอกเวลารันล่าสุด

### 5) เชื่อมแต่ละช่องทาง
แอป → หน้า **เชื่อมต่อช่องทาง** มี Webhook URL + ปุ่มคัดลอก:
- **LINE OA**: LINE Developers → Messaging API → วาง Webhook URL (`?ch=line`) → เปิด Use webhook → ปิดข้อความตอบกลับอัตโนมัติเดิมใน LINE OA Manager
- **Facebook/Instagram**: ข้อ 8
- **Google Maps**: ใส่ Place ID ของแต่ละสาขา → กด "ดึงรีวิวตอนนี้" ทดสอบ (ระหว่างรอ GBP)
- **ทางลัดทุกแอพ (Apify)**: ข้อ 9
- **ช่องทางอื่น**: ปุ่ม "เพิ่มรีวิวเอง" หรือ Generic Webhook (`?ch=generic` + header `x-webhook-key`)

### 6) Google Places (ใช้ระหว่างรออนุมัติ GBP) — ให้อยู่ในโควต้าฟรี
1. โปรเจกต์ Google Cloud ต้อง**ผูก billing account** (ไม่ผูก = Google ปฏิเสธทุกคำขอ แม้อยู่ในโควต้าฟรี)
2. เปิด **Places API (New)** และ **Places API (Legacy)** — ตัว Legacy ค้นหาไม่เจอให้เปิดจากลิงก์ตรง
   `https://console.cloud.google.com/apis/library/places-backend.googleapis.com` (ไม่เปิด = ได้แค่ 5 รีวิวเด่นซ้ำ ๆ ไม่ได้รีวิวใหม่)
3. จำกัด API key ให้ใช้ได้แค่ 2 API นี้
4. **ตั้งเพดาน**: APIs & Services → Places API (ทั้ง 2 ตัว) → Quotas → จำกัด **ไม่เกิน 30 ครั้ง/วัน** ต่อ API
   (30 × 31 วัน = 930 < ฟรี 1,000) แล้วตั้ง Billing → Budgets & alerts → งบ US$1
   — **งบนี้แค่ส่งอีเมลเตือน ไม่ได้ตัดการใช้งาน** ตัวที่กันเกินได้จริงคือเพดานรายวัน
   · ถ้าหน้า Quotas มีให้ตั้งแค่รายนาที: ตั้งแบบนั้นกันเกินรายเดือนไม่ได้ (1 ครั้ง/นาที = 1,440 ครั้ง/วัน) —
     ต้องพึ่งรอบดึงทุก 3 ชม. ของระบบ + อีเมลเตือนงบ และเปิด Billing → Reports ดูเดือนละครั้ง

### 7) Google Business Profile — รีวิวครบทุกอัน + ตอบรีวิวจากแอป (ฟรี)
1. **ยื่นขอสิทธิ์ API**: https://support.google.com/business/contact/api_default → "Application for Basic API Access"
   ส่งจากอีเมลเจ้าของ/ผู้จัดการ Business Profile + ใส่ Project number ของ Cloud · โปรไฟล์ต้องยืนยันแล้วและเปิดมา 60 วันขึ้นไป + มีเว็บไซต์
   รออนุมัติ **2–6 สัปดาห์** · ตรวจผล: Cloud Console → Quotas ของ 3 API ข้อ 2 ต้องขึ้น 300 ต่อนาที (ยังเป็น 0 = ยังไม่อนุมัติ)
2. เปิด API 3 ตัว: `Google My Business API` · `My Business Account Management API` · `My Business Business Information API`
3. **OAuth consent screen** (Google Auth Platform): External → **Audience → กด "Publish app"** (In production)
   — ถ้าค้างไว้แบบ Testing, Google ตัดสิทธิ์ทุก 7 วันและต้องกดเชื่อมต่อใหม่ทุกสัปดาห์ · บัญชีของร้านเองไม่ต้องผ่าน verification แค่กดผ่านหน้าเตือน "unverified app"
4. Credentials → OAuth client ID (Web application) → Authorized redirect URI:
   `https://aikyxvluaiubdidqxwnd.supabase.co/functions/v1/social-webhook`
5. ตั้ง secrets `GBP_CLIENT_ID` / `GBP_CLIENT_SECRET`
6. แอป → เชื่อมต่อช่องทาง → **เชื่อมต่อบัญชี Google Business ของร้าน** (เฉพาะบัญชีระดับผู้ดูแล/เจ้าของ · ลิงก์ใช้ได้ 15 นาที) → ยินยอม → กด **⟳ ซิงค์รีวิวทั้งหมด**
7. ซิงค์ครั้งแรกจะเจอรายชื่อโปรไฟล์ทั้งหมดที่บัญชีนี้ดูแล — โปรไฟล์ที่ชื่อไม่ตรงกับชื่อสาขาจะ**ยังไม่ถูกดึง**จนกว่าจะเลือกสาขา
   → เลือกสาขาใต้ปุ่มเชื่อมต่อ (โปรไฟล์ที่ไม่ใช่ของร้าน/ซ้ำ เลือก **"🚫 ไม่ดึง"**) → **💾 บันทึกสาขา** → กดซิงค์อีกครั้ง
   · บันทึกสาขาแล้ว รีวิวที่ดึงมาก่อนหน้าของโปรไฟล์นั้นย้ายสาขาตามให้ · เปลี่ยนเป็น "ไม่ดึง" แอปจะถามก่อนลบรีวิวของโปรไฟล์นั้นออกจากระบบ (รีวิวบน Google ไม่หาย)
   · ประวัติย้อนหลังเยอะ ซิงค์รอบเดียวไม่ทัน → แอปวนซิงค์ต่อให้เองจากจุดที่ค้าง (ค้างเกิน 2 ชม. เริ่มใหม่ — ของที่มีแล้วข้ามเร็ว)
   · Google ตอบผิดพลาดชั่วคราว ลองหน้าเดิมใหม่ 3 ครั้ง ยังไม่ได้ = การ์ดสถานะเตือน "ประวัติย้อนหลังยังไม่ครบ" ค้างไว้จนซิงค์ได้ครบ
   · เลือกสาขาให้โปรไฟล์ทีหลัง แอปจะถามว่าจะดึงย้อนหลังเลยไหม (ไม่ดึง = cron ได้แค่รีวิวใหม่ ๆ) · เชื่อมบัญชีใหม่ การเลือกสาขาเดิมยังอยู่
   · โปรไฟล์ของสาขาไหนดึงไม่ได้ สาขานั้นใช้ Place ID แทน — ไม่มี Place ID ของสาขานั้น การ์ดสถานะจะขึ้นแดงว่าไม่ได้รีวิวใหม่เลย

ได้อะไร: รีวิวย้อนหลังทุกอันของทุกสาขา (รวมทุกบัญชีธุรกิจที่ล็อกอินเห็น), คำตอบที่เคยตอบใน Google Maps ขึ้นว่า "ตอบแล้ว" ให้เอง,
ปุ่ม "ส่งตอบกลับ" บนรีวิว Google ใช้งานได้จริง · token เก็บแบบเข้ารหัส (AES-GCM)
เชื่อม GBP แล้ว cron จะใช้ GBP ก่อน (ฟรี) — Places ใช้เฉพาะตอน GBP ยังไม่พร้อม และกันรีวิวซ้ำข้ามสองแหล่งให้แล้ว

### 8) Facebook / Instagram (Meta — ฟรี)
1. Meta for Developers → Webhooks → Page: URL `?ch=facebook` + Verify token ให้ตรง `FB_VERIFY_TOKEN` → subscribe **`messages`, `feed`**
   Instagram: URL `?ch=instagram` → subscribe **`messages`, `comments`**
   (รีวิวเพจ/`ratings` — Meta ปิดไปแล้วตั้งแต่ปี 2025 ใช้ไม่ได้อีก)
2. `FB_PAGE_TOKEN` ต้องเป็น **Page token แบบไม่หมดอายุ**: เอา user token แบบ long-lived ไปขอ Page token (หรือใช้ System User token)
   — token จาก Graph API Explorer หมดอายุในไม่กี่ชั่วโมง (การ์ดสถานะจะเตือนถ้าหมดอายุ)
3. เปลี่ยนแอป Meta เป็น **Live** แล้วทดสอบทักแชท/คอมเมนต์ด้วยบัญชีที่**ไม่มีบทบาทในแอป**
   ถ้าไม่เข้า: ทำ Business Verification + App Review สิทธิ์ `pages_messaging`, `pages_manage_metadata`, `pages_read_engagement`, `pages_manage_engagement`, `instagram_manage_messages`, `instagram_manage_comments`
4. Messenger ส่งหาลูกค้าได้ภายใน 24 ชม. หลังข้อความล่าสุดของลูกค้าเท่านั้น (ระบบแจ้งเหตุผลให้ถ้าส่งไม่ได้)

1. สมัครฟรีที่ console.apify.com → **Settings → API & Integrations** → คัดลอก **Personal API token** (`apify_api_…`)
2. แอป → **เชื่อมต่อช่องทาง** → การ์ด **⚡ ดึงจากทุกแอพอัตโนมัติ** → วาง token → กด **เชื่อมต่อ** (ผู้ดูแลระบบ/เจ้าของเท่านั้น ·
   ฟังก์ชันตรวจกับ Apify แล้วเก็บแบบเข้ารหัส AES-GCM — กุญแจมาจาก service key แบบเดียวกับ refresh token ของ Google)
3. ใส่แหล่ง: ประเภท + ลิงก์/ชื่อบัญชี + สาขา + ความถี่ → **💾 บันทึก** → cron เริ่มเองภายใน 15 นาที (หรือกด **⟳ ดึงตอนนี้**)

| ประเภท | ใส่อะไร | ตัวดึงบน Apify | ตั้งต้น |
|---|---|---|---|
| 📍 รีวิว Google Maps | ลิงก์แชร์ร้าน (ต่อสาขา) | `compass/google-maps-reviews-scraper` — รอบต่อไปดึงเฉพาะรีวิวตั้งแต่รอบที่สำเร็จ | ทุกวัน |
| 🍜 รีวิว Wongnai | ลิงก์หน้าร้าน (ต่อสาขา) | `gravityzer0/wongnai-scraper` (ของชุมชน) | ทุก 3 วัน |
| 👍 รีวิวเพจ Facebook | ลิงก์เพจ | `apify/facebook-reviews-scraper` | ทุก 3 วัน |
| 💬 คอมเมนต์โพสต์ Facebook | ลิงก์เพจ | posts-scraper (4 โพสต์ ≤7 วัน) → comments-scraper (รวมคำตอบของเพจ) | ทุก 3 วัน |
| 📸 คอมเมนต์ Instagram | @บัญชีร้าน | instagram-post-scraper → instagram-comment-scraper | ทุก 3 วัน |
| 🎵 คอมเมนต์คลิป TikTok ของร้าน | @บัญชีร้าน | `clockworks/tiktok-scraper` → `clockworks/tiktok-comments-scraper` | ทุก 3 วัน |
| 🔎 คลิป TikTok ที่พูดถึงร้าน | คำค้น | `clockworks/tiktok-scraper` (ไม่ดาวน์โหลดวิดีโอ) | สัปดาห์ละครั้ง |

**กันค่าใช้จ่ายเกิน**: ทุกรอบส่ง `maxItems` + `maxTotalChargeUsd=0.1` + `timeout=300` · อ่านยอดใช้จาก `/users/me/limits` ทุกรอบ — ถึงงบ ($4.5 หรือ `APIFY_BUDGET_USD`, ไม่เกิน 95% ของเพดานบัญชี) = หยุดเริ่มรอบใหม่ ·
งบนับรวมรอบที่กำลังรัน (×$0.1) · อ่านยอดไม่ได้ = ไม่เริ่ม · **นับจากบัญชี Apify เอง** (`/actor-runs`): รันพร้อมกัน ≤3 · เริ่มใหม่ ≤8 รอบ/ชั่วโมง
(ตารางสถานะใครถือคีย์สาธารณะก็ลบได้ จึงไม่ใช้นับเพดาน) · เริ่มไม่เกิน 2 รอบต่อ 15 นาที · ดึงถี่สุดทุก 12 ชม. · ไม่เกิน 14 แหล่ง · กด "ดึงตอนนี้" แหล่งเดิมได้ทุก 30 นาที (ผู้ดูแลเท่านั้น)
· token เข้ารหัสแบบผูกกับจุดใช้ (AES-GCM + `additionalData`) และต้องขึ้นต้น `apify_api_` ถึงจะส่งออกไป · เปลี่ยนลิงก์/ประเภทของแหล่ง = เริ่มนับใหม่ (ทิ้งผลของลิงก์เดิม)
· Google Maps เลื่อนจุดเริ่มรอบหน้า (`ok_at`) เฉพาะรอบที่สำเร็จครบและบันทึกได้

**ทำงานยังไง**: cron ไม่รอให้ Apify ทำเสร็จ (ฟังก์ชันถูกตัดที่ 150 วิ) — รอบนี้สั่งเริ่ม รอบหน้าเก็บผล · สถานะอยู่ `social_settings` id `apify`
(`runs` รอบที่กำลังทำ · `last` ผลล่าสุดต่อแหล่ง · `usage` ยอดเครดิต · `lock` กันสองงานทำพร้อมกัน — แก้ด้วยการเทียบ `updated_at`)
· รีวิว Google กันซ้ำกับ Business Profile/Places (ชื่อ ±12 ชม. + ดาว + สาขา) · ไอดีคอมเมนต์ FB/IG แปลงให้ตรงกับที่ webhook เก็บ ·
ร้านตอบในแอพนั้นเอง → แถวขึ้น "ตอบแล้ว" (อัตราการตอบรายโพสต์ใช้ได้) · รีวิว Google ที่ร้านตอบใน Maps แล้วก็ขึ้นตอบแล้ว

ถ้าแหล่งไหนขึ้น ⚠️: `ข้อมูลที่ส่งให้ตัวดึงไม่ถูกต้อง` = ตัวดึงเปลี่ยนชื่อช่อง (แจ้งผู้ดูแลให้แก้โค้ด) · `ไม่พบตัวดึงข้อมูล` = ผู้พัฒนาเอาออกจาก Apify ·
`ได้ข้อมูลแต่อ่านไม่ออก` = รูปแบบผลเปลี่ยน · `แผนฟรีรันพร้อมกันได้จำกัด` = รอรอบหน้า (ไม่ต้องทำอะไร)

**รูปปกโพสต์/คลิป (v2026-10-07.4)** — แอปโชว์ FB/IG/TikTok เป็นช่อง ๆ แบบหน้าโปรไฟล์ IG · แตะช่อง = ฝังโพสต์/คลิปตัวจริง (ตัวเล่นทางการของแพลตฟอร์ม) + สรุปคอมเมนต์
· ลิงก์รูปของ IG/FB/TikTok หมดอายุในไม่กี่วัน และ IG/FB ไม่ให้เว็บอื่นแสดงรูปตรง ๆ → ฟังก์ชันคัดลอกรูปปกไปเก็บใน **Storage bucket สาธารณะ `social-media`**
(สร้างให้เองครั้งแรก · ≤1.5MB · jpg/png/webp · ดึงเฉพาะโดเมน CDN ของ 3 แพลตฟอร์ม) — ไม่ต้องรัน SQL · เก็บไม่ได้ = ขึ้น 🖼 ในการ์ด ⚡ และช่องเป็นตัวหนังสือแทน
· **เติมย้อนหลัง (v2026-10-07.6)**: ขั้นแรกอ่านโพสต์ล่าสุด 8 โพสต์ (ดึงคอมเมนต์ยังเฉพาะโพสต์ใหม่ ≤4) แล้วเติมข้อความ/รูปปกให้คอมเมนต์ที่เก็บไว้ก่อนหน้า
(`apBackfill` · จับคู่ด้วยลิงก์ หรือเลขโพสต์ Facebook เพราะลิงก์มี 2 แบบ pfbid…/เลขโพสต์ · เฉพาะแถวจาก Apify · ไม่เปลี่ยน = ไม่เขียน) · กด ⟳ ดึงตอนนี้ = เติมเลย

**รายการโพสต์/คลิปทั้งหมด (v2026-10-07.7)** — ระบบดึงคอมเมนต์อัตโนมัติเฉพาะ 4 โพสต์/คลิปล่าสุด (ประหยัดเครดิต) แต่จำ**ทุกโพสต์ที่เคยเห็น**ไว้ที่ `social_settings` id `ap_posts`
(≤100 ต่อช่องทาง · ข้อความ/วันที่/ยอด/รูปปก) → แอปโชว์ครบทุกช่อง โพสต์ที่ยังไม่มีคอมเมนต์ขึ้น "ยังไม่ได้ดึงคอมเมนต์"
· **📥 ดึงโพสต์/คลิปย้อนหลัง** (หน้าแพลตฟอร์ม · ผู้ดูแล/เจ้าของ · 30/60 รายการ · เพดาน $0.50 · ไม่ดึงคอมเมนต์) · **💬 ดึงคอมเมนต์ของโพสต์นี้** (หน้าโพสต์ · ทีละโพสต์)
— ทั้งสองปุ่มเรียก action `apify_more` (ต้อง `bossCheck`) · รอบพิเศษเก็บใน `runs`/`last` ด้วยคีย์ `<แหล่ง>~cat` / `<แหล่ง>~cm` · รูปปกที่เหลือทยอยเก็บรอบละ ≤8 (`apCatThumbs`)

**ดึงคอมเมนต์หลายโพสต์ในรอบเดียว (v2026-10-07.9)** — ปุ่ม **💬 ดึงคอมเมนต์ N โพสต์/คลิปที่ยังไม่ได้ดึง** (หน้าแพลตฟอร์ม · ผู้ดูแล/เจ้าของ) ส่ง `apify_more` พร้อม `urls`
(≤`AP_CM_BULK`=20 · ลิงก์ต้องเป็นของแพลตฟอร์มเดียวกับแหล่ง · ตัดซ้ำ) → รอบ Apify เดียว · คอมเมนต์ต่อโพสต์ลดตามจำนวนโพสต์ รวม ≤`AP_CM_MAX`=300 ·
เพดานเงิน `AP_CAT_USD` $0.50 (ไม่เกินงบที่เหลือ) · คีย์รอบ `<แหล่ง>~cm` (+ `max`) · ตอบ `{ok,key,n}` · ส่ง `url` ตัวเดียว = แบบเดิม (ทีละโพสต์)

**🚀 ดึงย้อนหลังทั้งหมด + คอมเมนต์ + วิเคราะห์ (v2026-10-07.11)** — ต้องรัน **`jjmk_social_posts.sql`** ก่อน (ตาราง `social_posts` เก็บทุกโพสต์ · แอปอ่านอย่างเดียว)
แล้วผู้ดูแล/เจ้าของกด **🚀 เริ่มดึงทั้งหมด** ในการ์ด ⚡ (action `apify_full`) → cron ทำเป็นรอบ ๆ ทุก 15 นาที ต่อแหล่ง FB/IG/TikTok คอมเมนต์:
1. อ่านรายการโพสต์/คลิปทั้งหมด ≤2,000 (`<แหล่ง>~all` · เพดาน $2 · ตัวดึงทำได้ถึง 1 ชม. · อ่านผลทีละ 300 แถว ข้ามรอบได้ · IG ไม่จำกัดวัน · TikTok รวมคลิปปักหมุด) → ลง `social_posts`
2. ดึงคอมเมนต์ทีละ 8 โพสต์ ใหม่ก่อน ≤300 คอมเมนต์/โพสต์ (`<แหล่ง>~fc` · เพดาน $1) · โพสต์ที่แพลตฟอร์มบอกว่าไม่มีคอมเมนต์ = ข้ามไม่เสียเงิน · พัง 2 ครั้ง = ข้าม
3. AI วิเคราะห์ตามเอง (Gemini ฟรี · ชุดละ 8 คอมเมนต์ต่อ 1 คำขอ · ข้อความยาว >700 ตัวอักษรทีละรายการ)

ใช้งบเดียวกับงานปกติ (หยุดเองที่ `APIFY_BUDGET_USD` ตั้งต้น $4.50/เดือน) — ไม่พอในเดือนเดียว = พัก แล้วทำต่อเองเมื่อเครดิตรอบใหม่เริ่ม ·
ครบทุกแหล่ง = จบงานเอง · กดหยุด/เริ่มใหม่ภายใน 30 วัน = ใช้รายการโพสต์เดิม (ไม่จ่ายค่าอ่านรายการซ้ำ) · โพสต์ที่ดึงคอมเมนต์แล้วไม่ดึงซ้ำ

## ข้อจำกัดที่ควรรู้

- **Google Places** ให้รีวิวรอบละ 5 เด่น + 5 ล่าสุดต่อสาขา (ระบบสะสมเพิ่มเรื่อย ๆ) และตอบรีวิวไม่ได้ — ได้ครบ+ตอบได้ต้องใช้ GBP
- **Gemini ฟรี** หมดโควต้ารายวันได้ (รีเซ็ตราว 14:00–15:00 เวลาไทย) — ระหว่างนั้นรีวิวใหม่ได้ผล `[เบื้องต้น]` ก่อน แล้ว cron อัพเกรดให้เองทีละน้อยด้วย Gemini ฟรีเท่านั้น (หยุดเมื่อใช้ Gemini รวมทุกงานถึง ~300 ครั้ง/วัน เผื่อโควต้าให้แชทบอท · Gemini ล่ม/ช้าแค่รอรอบหน้า ·
  รายการที่ Gemini ตอบกลับมาแต่ใช้ไม่ได้ (ถูกบล็อก) จะติดป้าย `[เบื้องต้น·AI ไม่ผ่าน]` ไม่วนกลับมาขวางคิว — กด "ลองใหม่" ในการ์ดสถานะได้)
- **บอทตอน AI ไม่ว่าง**: ตอบเองเฉพาะข้อความที่เหมือนคำถามใน FAQ ทุกตัวอักษร (ไม่นับช่องว่างและคำลงท้าย ครับ/ค่ะ/ไหม) · ถ้าแค่คล้าย หรือมีคำปฏิเสธ/ร้องเรียน (ไม่, ยกเลิก, แย่ ฯลฯ) จะเก็บคำตอบ FAQ เป็นร่างให้คนกดส่งแทน
- **ความปลอดภัย**: ตาราง `social_*` เปิดให้คีย์สาธารณะของแอปอ่าน/เขียนได้ (แบบเดียวกับทุกแอปในระบบ) — ระบบจึงไม่เก็บค่าลับใด ๆ ในตาราง และลบคีย์/โทเคนออกจากข้อความผิดพลาดทุกอันก่อนบันทึก
  · การเชื่อมบัญชี Google ตรวจว่าเป็นผู้ดูแลจากค่าแฮชรหัสผ่านใน `pnl_users` ซึ่งตารางนี้ก็อ่านได้ด้วยคีย์สาธารณะเช่นกัน — กันคนทั่วไปได้ แต่ยังไม่แน่นหนาจนกว่าจะย้ายการล็อกอินของทุกแอปไปตรวจฝั่งเซิร์ฟเวอร์
- **ตอบจากแอปได้จริง**: แชท LINE/Messenger/IG DM + คอมเมนต์ FB/IG + รีวิว Google (เมื่อเชื่อม GBP) · ช่องทางอื่นใช้ปุ่มคัดลอกคำตอบ
- **Apify** ใช้ตัวดึงของผู้พัฒนาภายนอก (บางตัวเป็นของชุมชน) — เว็บต้นทางเปลี่ยนเมื่อไรอาจพังชั่วคราว และการดึงหน้าเว็บขัดเงื่อนไขการใช้งานของบางเว็บ
  (ดึงเฉพาะหน้าสาธารณะของร้านเราเอง ไม่ล็อกอินบัญชีร้าน · ข้อมูลที่ได้ผ่าน `maskPII` ก่อนส่ง AI เหมือนช่องทางอื่น)
- Grab/LINE MAN ไม่มี API รีวิวสาธารณะ และรีวิวอยู่หลังล็อกอินร้านค้า — รับผ่าน Generic Webhook หรือเพิ่มเอง
