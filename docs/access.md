### ลืมรหัสผ่าน — รหัส 6 หลักส่งเข้ากลุ่ม LINE (เจ้าของสั่ง 2026-09-29)

- หน้าล็อกอินของ `index.html` มีปุ่มรอง **"🔑 ลืมรหัสผ่าน"** ใต้ปุ่มสมัคร → ใส่ชื่อผู้ใช้ → ระบบสุ่ม**รหัส 6 หลัก**ส่งเข้า**กลุ่ม LINE เดียวกับที่แจ้งใบสมัคร**
  (`pnl_settings.line_group_id`) → พนักงานขอรหัสจากหัวหน้าในกลุ่ม → ใส่รหัส + รหัสผ่านใหม่ + ยืนยัน → ตั้งเสร็จเข้าได้เลย
  - **รหัสไม่ได้ส่งเข้ามือถือพนักงาน** — ตั้งใจให้หัวหน้าเป็นคนบอก (ทำหน้าที่อนุมัติไปในตัว) · กลุ่มนี้จึงควรเป็นกลุ่มหัวหน้า/ผู้ดูแลเท่านั้น
  - ฝั่งแอพ: `showReset`/`rqStep1`/`rqStep2`/`rqAsk`/`rqConfirm`/`rqDone` · เบราว์เซอร์คิด `pwHash()` เองแล้วส่งแค่แฮช — **รหัสผ่านตัวจริงไม่เคยออกจากเครื่อง**
- **ใช้ Edge Function ตัวเดิม `signup-notify`** (ไม่ได้แยกตัวใหม่ — เจ้าของ deploy ฟังก์ชันเดียว secret เดียว) แยกงานด้วยช่อง `action`:
  `reset_request` / `reset_confirm` ตอบเป็น JSON `{ok,reason}` · ไม่มี action = แจ้งใบสมัครแบบเดิม (ตอบเป็นข้อความ)
  - สถานะคำขอเก็บที่ `pnl_settings` แถว `reset:<username>` = `{h,exp,iat,n}` — `h` เป็น **HMAC ของรหัส** (กุญแจ = secret ในฟังก์ชัน)
    **ห้ามเก็บรหัสจริงลงตาราง** (anon อ่านได้) · อายุ 10 นาที · ใส่ผิดได้ 5 ครั้ง · ขอใหม่ได้ทุก 60 วินาที · สำเร็จแล้วลบแถวทิ้ง + ลง `pnl_access_log` + แจ้งกลุ่มว่าเปลี่ยนแล้ว
  - บัญชี `pending`/`rejected`/`active=false` ขอรหัสไม่ได้
  - **เขียนแถวคำขอแบบเทียบแล้วค่อยเขียน (`casReset`)** — POST ไม่มี on_conflict (ชน = 409) / PATCH มีเงื่อนไข `val=eq.<ค่าเดิม>`
    กดขอพร้อมกันหลายครั้ง = ส่งรหัสเข้ากลุ่มครั้งเดียว · เดารหัสพร้อมกันกี่คำขอก็นับครบ (จองสิทธิ์ลองก่อนเทียบรหัส) ·
    รหัสถูกส่งพร้อมกัน = สำเร็จครั้งเดียว (ปิดรหัสก่อนเปลี่ยนรหัสผ่าน) · **ห้ามกลับไปใช้ อ่าน→เขียนทับ** (ตรวจอิสระ 2026-09-29 เจอว่าทำให้เดาได้เกิน 5 ครั้ง)
  - ใส่ผิดครบ = เก็บแถว `{iat,n:5}` ไว้ (ไม่มีรหัส) — ห้ามลบ ไม่งั้นขอรหัสใหม่ได้ทันที ข้ามช่วงรอ 60 วินาที
  - ขอซ้ำภายใน 60 วินาทีทั้งที่รหัสเดิมยังใช้ได้ = ตอบ `{ok:true,again:true}` (ไม่ส่งรหัสใหม่) → แอพพาไปหน้าใส่รหัสเดิม
  - **ชื่อผู้ใช้เทียบตัวพิมพ์เป๊ะแบบเดียวกับล็อกอิน** (`pwHash` ผูกกับชื่อ) — ฟังก์ชันหาแบบตรงก่อน ไม่เจอค่อย `ilike` (escape `\ % _` · ชื่อมี `*` ไม่ลอง)
    แล้วตอบ `username` ชื่อจริงกลับไป · `reset_confirm` ด้วยตัวพิมพ์ไม่ตรง = ตอบ `{retry:true,username}` (ก่อนดูรหัส จึงไม่เสียสิทธิ์ลอง)
    แอพคิด `pwHash` ใหม่ด้วยชื่อจริงแล้วส่งอีกรอบ · **ห้ามแปลงชื่อผู้ใช้เป็นตัวเล็ก** (บัญชีที่ admin สร้าง เช่น `Kim` จะตั้งรหัสใหม่แล้วล็อกอินไม่ได้)
  - **ปุ่ม 🔑 ลืมรหัสผ่านซ่อนไว้จนกว่า `pnl_settings.reset_ready` ≥ `RESET_MIN`** (ใน `index.html`) — ฟังก์ชันรุ่นเก่าไม่รู้จัก `action`
    จะส่ง "มีคนสมัครใหม่" ปลอมเข้ากลุ่มทุกครั้งที่กด · ธงตั้งโดยฟังก์ชันเอง (ส่งข้อความทดสอบสำเร็จ) + ปุ่ม 🔎 ทดสอบ ใน JJ Access
    (รุ่นเก่ากว่า `fnVer()` = ล้างธงเป็นค่าว่าง) · เทียบเวอร์ชันด้วย `verCmp()` ห้ามเทียบสตริง (`.10` < `.3`)
    · การ์ด 🔔 ใน JJ Access มีแถบ `#rqState` บอกว่าปุ่มโผล่หรือยัง + ขั้นตอนข้อ 5 "กด 🔎 ทดสอบ" (เจ้าของ deploy แล้วงงว่าปุ่มไม่มา 2026-09-29
    เพราะขั้นตอนเดิมจบที่ตั้ง secret) · `RQ_MIN` ใน jjmk-admin.html **ต้องตรงกับ `RESET_MIN` ใน index.html**
    · ฟังก์ชันรุ่นใหม่เจอ `action` ที่ไม่รู้จัก = ตอบ `skip:` ไม่ส่งอะไรเข้ากลุ่ม
  - `fnVer()` อ่านเวอร์ชันจากบล็อก `fnSignupNotify` **ตอนเรียกใช้** — บล็อกอยู่ท้ายไฟล์ อ่านตอนโหลดสคริปต์จะได้ค่าว่าง (เคยพลาด)
  - แอพ: กันกดซ้ำด้วย `RQ.busy` + `RQ.seq` (คำตอบที่มาช้าหลังเปลี่ยนหน้าถูกทิ้ง) · ขั้นใส่รหัสจำไว้ใน `sessionStorage.jjhub_reset`
    (ลากหน้าลง/สลับไปดู LINE แล้วกลับมาอยู่หน้าเดิม) · ขั้นที่ 1 มีปุ่ม "มีรหัสแล้ว — ไปหน้าใส่รหัส" · ข้อผิดพลาดของเซิร์ฟเวอร์
    (`error:`/5xx) แยกจาก "โค้ดรุ่นเก่า" · งานรีเซ็ตตอบ JSON เสมอแม้ฐานข้อมูลล่ม
  - ทดสอบโดยรันโค้ดฟังก์ชันจริง (transpile ด้วย typescript) กับฐานข้อมูลจำลอง + เบราว์เซอร์จริง — ทั้งหมดอยู่ `/tmp` ของ session
  - ฟังก์ชันมี `const VERSION` และตอบ `sent | v<เวอร์ชัน>` → ปุ่ม 🔎 ทดสอบใน JJ Access บอกว่าโค้ดที่ deploy อยู่เป็นรุ่นไหน
    (ไม่มี `| v` = รุ่นเก่า → ระบบลืมรหัสผ่านยังไม่ทำงาน) · แอพอ่านเวอร์ชันที่คาดหวัง (`FN_VER`) จากบล็อก `fnSignupNotify` ที่ฝังในไฟล์เอง
  - ฟังก์ชันรุ่นเก่าตอบข้อความธรรมดา → `rqCall()` แปลงเป็น "ระบบลืมรหัสผ่านยังเป็นโค้ดรุ่นเก่า — แจ้งผู้ดูแล" (ไม่ค้าง ไม่พัง)
  - ตอบ `skip: อ่าน LINE_TOKEN ไม่เจอ | เห็น: <ชื่อ secret> | v…` — บอกแค่**ชื่อ** secret ที่ฟังก์ชันเห็น (ไม่มีค่า) ใช้แยกว่า "ยังไม่ได้ตั้ง" กับ
    "ตั้งแล้วแต่ยังไม่ได้ Deploy ซ้ำ" (เจ้าของเจอจริง 2026-09-29: ตั้ง secret หลัง deploy แล้วฟังก์ชันยังไม่เห็น → กด Deploy ซ้ำแล้วหาย)

### พนักงานลาออก — ปิดบัญชี ไม่ใช่ลบ (เจ้าของถาม 2026-09-29)

### หน้าล็อกอินมาตรฐาน — JJ Login (เจ้าของเลือกแบบ A 2026-09-28)

**ทุกแอพใช้หน้าล็อกอินหน้าตาเดียวกันหมด** — พื้นแดงเข้ม การ์ดโปร่งขอบทอง ปุ่มแดงไล่เฉด
พร้อม **ไอคอนประจำแอพ** (ชุดเดียวกับหน้าศูนย์รวมแอพเป๊ะ) + โลโก้ร้านเป็นตราเล็กมุมขวาล่าง
เพื่อเตือนว่ากำลังเข้าแอพไหน (เจ้าของสั่ง: "อยากให้มีไอคอนของแต่ละระบบ เตือนเวลา login ด้วย")

- โค้ดคือบล็อก `window.JJLogin` (+ CSS ในตัว) ฝังก่อน `</head>` ของ **15 ไฟล์**:
  `index.html` · `jjmk-pnl.html` · `jjmk-owner.html` · `jjmk-admin.html` · `jjmk-payroll.html` ·
  `jjmk-calendar.html` · `jjmk-invoice.html` · `jjmk-social.html` · `jjmk-maint.html` ·
  `jjmk-kpi.html` · `jjmk-stockcheck.html` · `jjmk-kitchen.html` · `jjmk-order.html` · `jjmk-office.html` · `jjmk-allergy.html`
  — **บล็อกเหมือนกันทุกไฟล์ ต่างแค่ `var APP=` บรรทัดแรก · แก้ที่ไหนต้องแก้ให้ครบทุกไฟล์**
  (วิธีที่ใช้จริง: แก้ไฟล์ต้นฉบับแล้ว sync ทับทุกไฟล์ด้วยสคริปต์ อย่าไล่แก้มือทีละไฟล์)
- ทะเบียนแอพอยู่ในตัวแปร `A` ของบล็อก (อิโมจิ + ชื่อ + คำอธิบาย + สีไล่เฉด) — **ต้องตรงกับไอคอนใน `index.html`**
  · คีย์ `hub` เป็นกรณีพิเศษ: ใช้โลโก้ร้านเป็นไอคอนหลักแทนอิโมจิ (`logo:1`)
- **วิธีใช้ 2 แบบ**
  - `JJLogin.mount('<id กล่องล็อกอินเดิม>', {...})` — วางการ์ดลงในกล่องเดิมของแอพ (กล่องเดิมยังคุมการเปิด/ปิดเหมือนเดิม)
  - `JJLogin.wrap({...})` คืน HTML ไปใส่เอง แล้วเรียก `JJLogin.bind({...})` ผูกปุ่ม/Enter (ใช้ในแอพที่สร้างหน้าล็อกอินด้วย JS: P&L · Owner · KPI)
- **ตัวเลือกสำคัญ**: `uid`/`pid`/`msgId`/`btnId` = id เดิมที่โค้ดแอพใช้อยู่ (ไม่ต้องรื้อ `doLogin()`) ·
  `submit` = ฟังก์ชันที่จะเรียก · `keepId` = ช่องติ๊ก "จำไว้ 12 ชม." · `lock` = แถบ 🔒 เปิดจากลิงก์ตรง ·
  `fields:false` + `beforeFields`/`beforeMsg` = ใส่ช่องกรอกเองทั้งหมด (ครัวกลาง/สั่งอาหาร QR ใช้แบบนี้) ·
  `extra` = ปุ่มรอง (`class="jjlg-btn2"`) · `note` = ข้อความท้ายการ์ด
- **`JJGate.note()` ใช้แถบ 🔒 ของ JJ Login แล้ว** (ถ้าเจอ `#jjlgLock`) — ไม่แปะกล่องของตัวเองซ้ำ
- **ห้ามลืม**: แอพที่ผูกปุ่มเอง (`el.onclick=doLogin`) ต้องเอาออกถ้าส่ง `submit` ให้ `mount()` แล้ว
  ไม่งั้น `doLogin()` ทำงาน 2 รอบ (เคยพลาดที่ซ่อมบำรุง) · โค้ดที่ตั้ง `.src` ของรูปโลโก้เดิมในหน้าล็อกอิน
  ต้องเช็ค null ก่อน (element เดิมถูกแทนแล้ว)
- **เขียนแอพใหม่**: ฝังบล็อก JJ Login (ตั้ง `APP` ให้ตรงกับ `data-app` ในหน้าศูนย์รวมแอพ) → เพิ่มแอพลงตัวแปร `A` ทุกไฟล์ → `JJLogin.mount()`
- เทสอยู่ที่ `/tmp` ของ session (ไม่ได้ commit) — เช็คอย่างน้อย: หน้าล็อกอินขึ้น · id ช่อง/ปุ่มครบ ·
  รหัสถูกเข้าได้ · รหัสผิดขึ้นข้อความ · จอ 360px ไม่เลื่อนแนวนอน · ช่องกรอก ≥16px · ปุ่ม ≥44px

### ด่านกันลิงก์หลุด — JJ Gate (เจ้าของสั่ง 2026-09-21)

**กติกา: เข้าจากหน้าศูนย์รวมแอพ = ใช้ได้เลยตามสิทธิ์ · เข้าด้วย URL ตรง = ต้องใส่รหัสผ่านใหม่ทุกครั้ง**
(กันกรณีลิงก์ถูกส่งต่อ แล้วเครื่องนั้นมี session ค้างอยู่ → เดิมเปิดเข้าได้เลย)

- โค้ดด่านคือบล็อก `window.JJGate` (+ `<style>` คู่กัน) ฝังไว้ก่อน `</head>` ของ **9 ไฟล์**:
  `index.html` · `jjmk-pnl.html` · `jjmk-owner.html` · `jjmk-admin.html` · `jjmk-payroll.html` ·
  `jjmk-calendar.html` · `jjmk-invoice.html` · `jjmk-office.html` · `jjmk-allergy.html`
  — **บล็อกเหมือนกันทุกไฟล์ ต่างแค่ `var APP=` บรรทัดแรก · แก้ที่ไหนต้องแก้ให้ครบทุกไฟล์**
- **JJ Social + ซ่อมบำรุง ไม่ได้ฝังบล็อกนี้** — สองแอพนั้นมีระบบของตัวเองที่ทำเรื่องเดียวกัน
  (ใบผ่าน `jjsso_ticket` + session ประจำแท็บใน `sessionStorage`) ทำงานร่วมกันได้ ไม่ต้องรวมเป็นอันเดียว:
  หน้าศูนย์รวมแอพออกใบผ่าน **ทั้งสองแบบ** ตอนคลิก (`JJGate.issue` + `issueTicket`)
  และ `JJGate.ok()` รับใบผ่านแบบ `jjsso_ticket` ได้ด้วย · **ใช้ใบผ่านแล้วลบทิ้งทั้งคู่** (ฟังก์ชัน `burn()`)
  ไม่งั้นใบที่เหลือค้างจะถูกเอาไปเปิดแท็บใหม่เข้าได้อีก
- ผ่านด่านได้ 3 ทาง (ฟังก์ชัน `JJGate.ok(username)`):
  1. **ใบผ่านประจำแท็บ** (`sessionStorage['jjgate_<app>']`) — ดึงหน้าลง/กดรีเฟรชแล้วยังอยู่ · แท็บใหม่ไม่มี · ไม่ขยับเกิน 30 นาทีแล้วรีเฟรช = ยืนยันใหม่
  2. **ใบผ่านครั้งเดียวจากหน้าศูนย์รวมแอพ** (`localStorage['jjhub_pass']`) — หน้าแรกออกให้ตอนกดไอคอน อายุ 2 นาที ผูกกับชื่อผู้ใช้+ชื่อแอพ ใช้แล้วลบทิ้ง
  3. **เปิดจากไอคอนที่ติดตั้งบนหน้าจอมือถือ (PWA standalone)** — ถือว่าเป็นเครื่องของเจ้าตัว
     (ลิงก์ที่ส่งต่อทางแชทเปิดในเบราว์เซอร์ธรรมดา ไม่เข้าเงื่อนไขนี้)
- ไม่ผ่าน → แอพแสดงหน้าล็อกอินของตัวเอง + ข้อความ "🔒 เปิดจากลิงก์ตรง" + เติมชื่อผู้ใช้ให้ (`JJGate.note(user,'liUser','liPass')`)
  · ล็อกอินสำเร็จทุกแอพต้องเรียก **`JJGate.grant(username)`** ไม่งั้นรีเฟรชแล้วจะถามรหัสซ้ำ
- หน้าศูนย์รวมแอพออกใบผ่านด้วย `JJGate.issue(app, ME.username)` ตอนคลิกไอคอน — **ยังไม่ล็อกอิน = ไม่ออกให้** (แอพปลายทางจะถามรหัสเอง) · `logout()` ล้าง `jjhub_pass` ด้วย
- **เพิ่มแอพใหม่ที่ใช้ `pnl_users`** ต้องทำ 3 อย่าง: ฝังบล็อก JJ Gate (ตั้ง `APP` ให้ตรง `data-app`) · เช็ค `JJGate.ok()` ก่อนยอมรับ session ที่เก็บไว้ · เรียก `JJGate.grant()` ตอนล็อกอินสำเร็จ
- ช่องล็อกอินบนมือถือถูกบังคับเป็น 16px (`#lgU,#lgP,#liUser,#liPass`) กัน iPhone ซูมหน้าจอเองตอนกดพิมพ์
- เช็คบัญชีกับฐานข้อมูลไม่ได้ (เน็ตล่ม/ตาราง error) = **ไม่ปล่อยเข้า** แล้ว — เดิม P&L/Owner หลุดเป็น `legacy` ที่เป็น admin (ยกเว้นตาราง `pnl_users` ไม่มีจริง = HTTP 404 ถึงจะเข้าโหมดเดิม)

### ระดับตำแหน่ง + สังกัด (เจ้าของสั่ง 2026-09-18)

บัญชีใน `pnl_users` มี 2 มิติ — ตั้งที่หน้า JJ Access → ผู้ใช้ & สิทธิ์ → ✏️ (SQL: `jjmk-access-unit.sql`)

| `role` (ระดับ) | ได้อะไร |
|---|---|
| `admin` 🛡️ ผู้ดูแลระบบ | ทุกสิทธิ์ทุกแอป + เข้าหน้า JJ Access จัดการผู้ใช้ |
| `owner` 👑 เจ้าของ | เหมือน admin (ทุกแอป + จัดการผู้ใช้) |
| `manager` 📋 ผู้จัดการ | ตามสิทธิ์รายแอปที่ตั้งให้ · เข้า JJ Access ไม่ได้ |
| `staff` 👤 พนักงาน | ตามสิทธิ์รายแอปที่ตั้งให้ · เข้า JJ Access ไม่ได้ |

| `unit` (ประจำที่) | |
|---|---|
| `ALL` ส่วนกลาง · `OFFICE` ออฟฟิศ · `JJCK` ครัวกลาง · `JJLP` สาขาลาดพร้าว · `JJRD` สาขารัชดา | |

- ฐานข้อมูลมี CHECK constraint คุมค่าทั้ง `role` และ `unit` — เพิ่มค่าใหม่ต้องแก้ constraint ด้วย
- (2026-09-21 แก้แล้ว: `jjmk-owner.html` เคยเช็ค `role==='admin'` ตรง ๆ ทำให้บัญชีระดับ **เจ้าของ** เข้าหน้าเจ้าของไม่ได้ · `jjmk-social.html` `isAdmin()` และ `jjmk-calendar.html` `canEdit()` ก็แก้ให้นับ `owner` ด้วยแล้ว)
