## ระบบปฏิทินองค์กร (JJ Calendar)

- แอปคือ `jjmk-calendar.html` ที่ root (สร้าง 2026-09-10) — ปฏิทินนัดหมายภายในองค์กร: สร้างนัด ระบุผู้สร้าง/ผู้เข้าร่วม มุมมองเดือน+รายการนัด
- ตาราง Supabase ใช้ prefix `cal_` (`cal_events`/`cal_attendees`/`cal_settings`) · ล็อกอินใช้ `pnl_users` ร่วมกับ P&L · สาขาอ่านจาก `pnl_branches` (+ JJCK/OFFICE เพิ่มในแอป)
- SQL ติดตั้งคือ `jjmk-calendar.sql` ที่ root ของ branch `sql`
- เพิ่มนัดลงมือถือได้ 2 ทาง: ดาวน์โหลด `.ics` ต่อนัด (มี VALARM เตือนตาม `reminder_min`) / subscribe ฟีดทั้งปฏิทินผ่าน Edge Function **`cal-feed`** (deploy ผ่าน Dashboard · **ปิด Verify JWT** · URL ต้องมี `?token=` ตรงกับ `cal_settings` id=`feed` · `&user=` = กรองเฉพาะนัดของคนนั้น)
- นัดทั้งวันเก็บ `start_at`/`end_at` เป็น 00:00 เวลาไทยของวันแรก/วันสุดท้าย (นับรวม) — ฝั่ง ICS แปลง DTEND เป็น exclusive (+1 วัน) ให้แล้ว
- ยกเลิกนัด = `cancelled=true` (soft delete) → หายจากแอปและฟีดมือถือตอนรีเฟรช
- **แก้ปัญหาฟีดไม่ทำงาน** (ปุ่ม 🔎 ทดสอบในแท็บ "เชื่อมมือถือ" แยกอาการให้แล้ว): `401` = Supabase ปัดตกตั้งแต่ด่านหน้า → ยังไม่ได้ deploy `cal-feed` **หรือยังไม่ได้ปิด Verify JWT** (แอปยิงซ้ำแบบแนบ key เพื่อแยกสองกรณี: ได้ 404 = ยังไม่ deploy · ได้ 200/403 = ยังไม่ปิด JWT) · `403` = token ไม่ตรงกับ `cal_settings`
- **โค้ด `cal-feed` อยู่ในแอปแล้ว** — ฝังเป็น `<script type="text/plain" id="feedCode">` ในหัวไฟล์ + ปุ่ม 📋 คัดลอกในแท็บ "เชื่อมมือถือ" (เห็นเฉพาะ `isBoss()`) · **แก้โค้ดฟีดต้องแก้ 2 ที่ให้ตรงกัน**: บล็อกนี้ กับ `cal-feed.ts` ที่ branch `sql`
- โค้ดฟีดเป็น **TypeScript วางที่ Edge Functions เท่านั้น** — ถ้าวางใน SQL Editor จะขึ้น `syntax error at or near "//"` (เคยพลาดมาแล้ว 2026-09-21 · ขั้นตอนติดตั้งจึงอยู่ในแอปแล้ว)
- `fold()` ในโค้ดฟีด **ต้องพับบรรทัดตามจำนวนไบต์ (74) และเดินด้วย `for...of`** — ของเดิมหั่นทีละ 73 ตัวอักษร JS ทำให้อีโมจิถูกหั่นกลางตัว (surrogate เดี่ยว) และบรรทัดยาว 200+ ไบต์ เกินมาตรฐาน RFC 5545 (แก้แล้ว 2026-09-21)
- ⚠️ **ห้ามเขียนไฟล์โค้ดที่มีแบ็กสแลชด้วย bash heredoc** — สภาพแวดล้อมนี้กลืนแบ็กสแลชในลำดับ `\\;` (พิสูจน์แล้ว 2026-09-21: `E\\;F` กลายเป็น `E\;F`) ทำให้ `esc()` ของฟีดไม่ escape `;` ให้ใช้ python เขียนไฟล์แทน และตรวจไบต์จริงด้วย `od -c` ทุกครั้ง
- `500` จากฟีด = ผ่าน Verify JWT แล้วแต่โค้ดพัง — **ฟังก์ชันตอบสาเหตุกลับมาเป็นข้อความ** และปุ่มทดสอบในแอปเอามาแสดงให้เลย · โปรเจกต์นี้ใช้คีย์แบบใหม่ (`sb_publishable_...`) คีย์ legacy `SUPABASE_SERVICE_ROLE_KEY` อาจใช้ไม่ได้ → `sbGet()` จึง**ลอง service role ก่อนแล้วสลับไป `SUPABASE_ANON_KEY` เอง** (ตาราง `cal_*` เปิด select ให้ anon อยู่แล้ว)
- **ปุ่มแตะครั้งเดียว (2026-09-21)**: แท็บ "เชื่อมมือถือ" มีปุ่มใหญ่ 2 ปุ่ม — iPhone ใช้ลิงก์ `webcal:` (เปิดแอปปฏิทินให้เลย) · Android ส่งไป `calendar.google.com/calendar/render?cid=<webcal url>` · เรียงปุ่มตามเครื่องที่เปิด และแอปตรวจฟีดให้เองตั้งแต่เปิดหน้า (ฟีดไม่พร้อม = ปุ่มจางลงพร้อมบอกเหตุผล)
- ~~iPhone ห้ามใช้ `webcal:`~~ **ข้อมูลเดิมผิด** — ที่ iPhone ขึ้น "การตรวจสอบไม่สำเร็จ" ตอน 2026-09-21 เกิดจากฟีดตอบ 401 (ยังไม่ปิด Verify JWT) ไม่ใช่เพราะ scheme · `webcal:` เป็นวิธีมาตรฐานที่ Google/Outlook ใช้กันอยู่แล้ว · ถ้าแตะแล้วไม่ขึ้นจริง ๆ ค่อยใช้วิธีคัดลอก URL `https://` ไปวางใน การตั้งค่า → แอปปฏิทิน → เพิ่มปฏิทินที่ติดตาม (อยู่ในกล่อง "ปุ่มไม่ทำงาน?" ในแอป)

- **เรียลไทม์ + ตัวกรอง (2026-09-21)**: แอปต่อ Supabase Realtime (`supabase-js` จาก CDN · channel `jjcal-live` ฟัง `cal_events`/`cal_attendees`) → มีคนเพิ่มนัด คนอื่นเห็นทันที · **ต้องรัน `jjmk-calendar-realtime.sql` ครั้งเดียว** (เพิ่มตารางเข้า publication `supabase_realtime`) ไม่งั้นจะตกไปใช้โพลสำรองทุก 90 วินาที · จุด 🟢/⚪ ข้างชื่อผู้ใช้บอกสถานะการเชื่อมต่อสด · ไม่รีเฟรชทับตอนเปิด modal ค้างอยู่ (กันฟอร์มที่กรอกค้างหาย)
- ตัวกรองในหน้าปฏิทิน/รายการนัด: ค้นหา (หัวข้อ·สถานที่·รายละเอียด·ชื่อสาขา·ชื่อผู้เข้าร่วม) + เลือกดูปฏิทินของคนใดคนหนึ่ง + ปุ่มล้างตัวกรอง · เก็บใน `sessionStorage.jjcal_filter` (รีเฟรชแล้วยังอยู่ ปิดแท็บแล้วหาย) · กล่องเลือกผู้เข้าร่วมกรองตามสังกัด (`pnl_users.unit`) ได้ และ "เลือกทั้งหมดที่เห็น" จะเลือกเฉพาะที่ผ่านตัวกรอง

### 🎌 วันพิเศษกลาง — ปฏิทินเป็นที่ลงวันพิเศษให้ทุกระบบ (เจ้าของสั่ง 2026-09-29)

- เจ้าของ: *"อยากให้ทุกระบบใช้ปฏิทินนี้เป็นหลัก ลงวันหยุดพิเศษที่ต้องใช้ในระบบอื่น เช่น วันค่าแรง ×2 ใน payroll / วันที่ต้องสั่งของมากกว่าปกติในระบบสต๊อก"*
- ตาราง **`cal_special_days`** (SQL: `jjmk-calendar-days.sql` ที่ branch `sql` — ต้องรันครั้งเดียว) + `cal_special_days_log` (trigger จดเอง · anon อ่านได้อย่างเดียว)
  + view `cal_special_days_v` (1 แถว/วัน) · วันที่เป็นคอลัมน์ `date` ('YYYY-MM-DD' = วันของร้าน) **ไม่ใช่ timestamptz** — ห้ามแปลงผ่าน `new Date(str)` ใช้ `sdAdd()`
- **แยกเป็น 3 ปฏิทิน (เจ้าของสั่ง 2026-09-30)** — *"เรื่องปฏิทินจะต้องแยกเป็น 1.ปฏิทินที่ออฟฟิศหยุด 2.ปฏิทินที่พนักงานได้ค่าแรง ×2 3.ปฏิทินที่สั่งของเท่ากับวัน ส–อา"*
  · **1 แถว = 1 ปฏิทิน** (ช่อง `kind`) · วันเดียวกันอยู่หลายปฏิทินได้ (สงกรานต์ อยู่ทั้ง 3 ได้) · ปฏิทินเดียวกันห้ามซ้อนวัน (`cal_sd_off_once` / `cal_sd_pay_once`)
  - 🏢 `kind='office'` ออฟฟิศหยุด — **พนักงานสาขา `OFFICE`** ได้หยุด นับเป็นวันทำงาน · หน้าร้านทำงานปกติ (ไม่ได้ ×2 · ไม่ใช่วันห้ามหยุด) → เงินเดือน `holidays.scope='office'`
  - 💰 `kind='pay'` ค่าแรง ×N (`pay_multiplier` 1.5/2/3) — หน้าร้านได้ ×N + วันห้ามหยุด (ขาด = หัก 2 เท่า) · สาขา OFFICE ทำงานปกติ → `holidays.scope='store'`
  - 📦 `kind='order'` สั่งของแบบ ส–อา (`order_rate_group=2` · `order_branches` null = ทุกสาขา) → แอพนับสต๊อก + ครัวกลาง (บล็อก `SPD` ไม่ต้องแก้ — อ่านช่อง order เหมือนเดิม)
  - **"ออฟฟิศ" = พนักงานสาขา `OFFICE`** (เจ้าของเลือก — ไม่ใช่สวิตช์ holidayPay) · ใครได้ ×N หรือได้หยุด ยังตามสวิตช์ "ได้เบี้ยวันหยุดพิเศษ" ของคนนั้นเหมือนเดิม
  - `kind=null` = ป้ายเดิมจากรุ่นก่อนแยก (ไม่มีผลกับระบบไหน) — แท็บ 🎌 มีปุ่ม "→ 🏢/💰/📦" ย้ายเข้าปฏิทิน · SQL ย้ายแถวรุ่นก่อนให้เอง (แยกแถวที่มีหลายผลเป็นหลายแถว ไม่มีอะไรหาย)
  - `pay_scope` ยังเก็บ (office/store/all ตาม kind) แต่แอพใช้ `kind` เป็นหลัก
- **คำตอบเจ้าของ (2026-09-29) — กติกาที่ต้องคงไว้**:
  - 🏢/💰 **มีผลกับเงินเดือนก็ต่อเมื่อกด ✅ ยืนยันในหน้า 🎌 ของระบบเงินเดือนเท่านั้น** (`pay_status`: `pending` → `confirmed`/`declined`) · ระบบเงินเดือนยังคิดเงินจากตาราง `holidays` เดิม
    · แก้ชื่อ/วัน/ตัวคูณ = กลับเป็น `pending` เสมอ (`sdPayStatus`) · ยกเลิกวันที่เคยยืนยันแล้ว = `pending` (ให้เงินเดือนเอาออก)
  - ยาวไม่เกิน 32 วัน · ตัวคูณ 1.5/2/3 เท่านั้น
- แท็บ 🎌: ปุ่มเลือกปฏิทิน 3 ปุ่ม (`S.sdk` จำใน `localStorage.jjcal_sdk`) · ปุ่ม ＋ ของปฏิทินนั้น · **📋 เลือกจากวันหยุดราชการ** ใส่ลงปฏิทินที่เปิดอยู่ (ตั้งต้นไม่ติ๊กอะไร — เจ้าของเลือกเองทุกวัน)
  · หน้าเดือน: ปุ่ม ☑/☐ เปิด-ปิดแต่ละปฏิทิน (`jjcal_sdshow`) · สี: 🏢 ม่วง · 💰 ทอง · 📦 ฟ้า · โชว์ตามสาขาที่ดู (`sdHere`: 🏢 = OFFICE · 💰 = ไม่ใช่ OFFICE · 📦 = สาขาที่เลือก)
  · แตะวัน = การ์ดวันพิเศษ + ปุ่มใส่วันนั้นลง 3 ปฏิทิน · ยังไม่รัน SQL รุ่น 3 ปฏิทิน (`S.sdKindCol=false`) = บอกให้รัน ไม่ให้เพิ่ม
- แอพ: แท็บ **🎌 วันพิเศษ** (`vDays`) · ฟอร์ม `openDayForm`/`saveDay`/`cancelDay` · **📋 ใส่วันหยุดราชการทั้งปี** (`SD_PRESET` = วันที่ตายตัว 13 รายการ ·
  วันพระ/ลอยกระทง/ตรุษจีน/วันหยุดชดเชย เลื่อนทุกปี ให้กรอกเอง) · ช่องวันในหน้าเดือนเปลี่ยนสีพื้น (ไม่กินที่ 3 แถบนัด) · การ์ดวันพิเศษในหน้าต่างวัน +
  บนสุดของ "นัดที่จะถึง" · 🕘 ประวัติการแก้ (`sdHistory`) · วันที่ตั้งไว้ในหน้า 🎌 ของเงินเดือนอย่างเดียวโชว์เป็นการ์ดเทา (อ่านจาก `holidays`)
  - **ลง/แก้ได้เฉพาะ `isBoss()`** (ช่วงแรก) · แก้พร้อมกันกันด้วย PATCH มีเงื่อนไข `updated_at` · realtime ช่องแยก `jjcal-days` (ไม่มีตาราง = ช่องนัดหลักไม่หลุด)
  - **โหลดแบบ fail-soft** — ยังไม่รัน SQL ปฏิทินยังเปิดได้ปกติ แท็บ 🎌 บอกให้รัน SQL
  - ⚠️ **ปุ่มเลือกในฟอร์มวันพิเศษใช้ `data-sv` ห้ามใช้ `data-v`** — ตัวจับคลิกกลางของแอพถือว่า `[data-v]` คือปุ่มแท็บ (เคยพลาด: แตะ "รัชดา" แล้วเด้งไปแท็บที่ไม่มีจริง)
  - `jjcal_tab` ตรวจแล้วว่าเป็นแท็บที่มีจริง (`month`/`agenda`/`days`/`sync`) ตามกติกา UX
