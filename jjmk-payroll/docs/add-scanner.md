## สรุปสั้น (อ่านบนมือถือ)

1. **สาขา 3 ยังไม่ได้ซื้อเครื่อง** ให้ทำตาม "เส้นทางสาขา 3" ข้างล่าง: **อัปเดต Worker กับเลือกซื้อเครื่องทำได้ทันที ไม่ต้องรอกัน และไม่ต้องรอเปิดสาขา** · เปิดสาขาในระบบเมื่อรู้รหัส ชื่อ วันเปิดจริง และสาขาภาษีแน่นอนแล้ว → ตั้งสิทธิ์ผู้จัดการ → เช็คเน็ตสาขา 3 → เพิ่มพนักงาน → ลงหน้า → ชี้เครื่องมาที่ Worker → ผูกสาขา → ทดสอบในวันทำงานจริงก่อนเปิดร้าน
2. **ควรซื้อยี่ห้อและรุ่นเดียวกับเครื่องที่ใช้อยู่ ซึ่งส่งข้อมูลเข้าระบบนี้ได้แล้ว** · ระบบรับได้ 2 **วิธีส่งข้อมูล** (ADMS/iclock แบบ ZKTeco หรือ HTTP Listening แบบ JSON ของ Hikvision) Worker ไม่ได้ดูยี่ห้อ · ก่อนจ่ายเงินให้ถามร้านตามเช็กลิสต์ในหัวข้อ "ควรซื้อเครื่องรุ่นไหน"
3. ใช้ **Worker ตัวเดิม** `steep-hill-7d52.thananantpatt.workers.dev` ไม่ต้องสร้างใหม่ แต่ Worker ที่อยู่ใน Cloudflare ต้องเป็น**รุ่นใหม่** ถ้ายังเป็นรุ่นเก่า รายงาน LINE จะขึ้นรหัสสาขาแทนชื่อสาขา 3 และคนที่ Worker สร้างให้จะเป็นรายวัน 400 · Deploy มีผลกับเครื่องทุกสาขาทันที ต้องตรวจหลัง Deploy (ขั้น C)
4. **เพิ่มพนักงานในแอปก่อนชี้เครื่องมาที่ Worker** โดยใส่ทั้งรหัสและเลือกสาขา 3 · รหัสในเครื่องต้องตรงกับในแอปทุกตัวอักษร · คนที่ย้ายมาจากสาขาเดิมให้ใช้**รหัสเดิม** · **เพิ่มให้ใกล้วันลงหน้าที่สุด** เพราะพอมีพนักงานสาขา 3 แล้ว สรุป LINE 21:00 จะขึ้นทุกคนว่า "ไม่มา" ทุกคืนจนกว่าร้านจะเปิด
   - หลังเปิดสาขา ต้อง**โหลดหน้าแอปเงินเดือนใหม่** (กดรีโหลดของเบราว์เซอร์ หรือลากหน้าลง) สาขา 3 ถึงจะขึ้น · ปุ่ม "🔄 รีเฟรชข้อมูล" ในแอปไม่อ่านทะเบียนสาขาใหม่
5. **ลงหน้าและลองสแกนให้เสร็จก่อนชี้เครื่องมาที่ Worker** เพราะพอชี้แล้ว ทุกสแกนจะเป็นเวลาทำงานจริงที่ใช้คิดเงินทันที
6. **ผูกเครื่องกับสาขาในแอปเงินเดือน**: ⚙️ ตั้งค่า → การ์ด "📟 เครื่องสแกน → สาขา" (ใช้ SQL เฉพาะเมื่อทำในแอปไม่ได้)
7. **นาฬิกาเครื่องต้องเป็นเวลาไทย GMT+7** ระบบบันทึกเวลาตามที่เครื่องส่งมา ไม่มีขั้นไหนช่วยแก้ให้
8. **ทดสอบด้วยเวลาเข้า-ออกงานจริง ในวันทำงานจริงก่อนเปิดร้าน แล้วดูว่าชื่อขึ้นในแอป รายงาน LINE และจอ KPI** เครื่องขึ้น "ส่งสำเร็จ" ยังไม่พอ เพราะ Worker ตอบ OK เสมอ (worker.js:151-155)

### A. เช็คว่าสาขา 3 เปิดในระบบแล้วหรือยัง (~2 นาที)

- เปิด **JJ Access** → แท็บ **🏪 สาขา** (เห็นเฉพาะบัญชี admin/owner · docs/branches.md:19) จะเห็นได้ 3 แบบ:
  - ถ้ามีสาขา 3 ในรายการ และไม่มีกล่องเตือนสีทองด้านบน แปลว่าเปิดแล้ว ให้จด**รหัส**ของสาขา 3 ไว้ แล้วข้ามไปขั้น B2
  - ถ้าขึ้นกล่อง "⚠️ ยังไม่ได้ติดตั้งระบบสาขากลาง" แปลว่ายังไม่ได้รัน `jjmk-branches.sql` (admin.html:2293) ให้ Claude แปะ SQL ให้ในแชทก่อน
  - ถ้าขึ้นกล่อง "⚠️ อ่านทะเบียนสาขาจากฐานข้อมูลไม่ได้ (เน็ต/เซิร์ฟเวอร์)" (admin.html:2297) รายการที่เห็นเป็นของที่จำไว้ในเครื่อง อาจเก่า และปุ่ม ➕ เปิดสาขาใหม่จะกดไม่ได้ (admin.html:2303) · **อย่าเพิ่งสรุปว่ายังไม่เปิดสาขา** ให้กด 🔄 ลองใหม่ หรือโหลดหน้าใหม่ หรือใช้ SQL ด้านล่างแทน
- หรือดูใน Supabase → SQL Editor (อ่านอย่างเดียว):

```sql
-- สาขาที่อยู่ในทะเบียนกลาง (อ่านอย่างเดียว)
select * from pnl_branches order by code;
```

### B. เปิดสาขา 3 (ถ้ายังไม่เปิด)

**ทำเมื่อไหร่**: เมื่อรู้แน่แล้วว่ารหัส ชื่อ วันเปิดร้านจริง และสาขาภาษีเป็นอะไร · ไม่ต้องรีบเปิดเพื่อไปซื้อเครื่อง (ขั้น D ไม่ต้องรอขั้นนี้) · แต่ต้องเสร็จก่อนขั้น E

JJ Access → 🏪 สาขา → **➕ เปิดสาขาใหม่** → ทำตามวิซาร์ด 5 ขั้น (docs/branches.md:19-23 · admin.html:2247):
① ใส่รหัส (ตัวอังกฤษพิมพ์ใหญ่ล้วน 2–8 ตัว ระบบใช้เป็นตัวหน้าเลขใบกำกับภาษีไปตลอด admin.html:2415) ชื่อ ชื่อสั้น สี วันเปิด เลขบิลใบแรก สาขาภาษี · ② เลือกสาขาต้นแบบ · ③ เลือกสินค้านับสต๊อก · ④ กลุ่มไลน์ KPI, QR, ลิงก์รีวิว · ⑤ ยืนยัน

> ⚠️ **ในขั้น ① ให้เปลี่ยน "วันเปิดสาขา" เป็นวันเปิดร้านจริง** ช่องนี้ตั้งไว้ให้เป็น**วันนี้** (admin.html:2362 `brToday`) ถ้าไม่แก้ ตั้งแต่พรุ่งนี้ ออฟฟิศ AI จะขึ้นแดงทุกวันว่า "สาขา 3 ยังไม่ลงยอดขายเมื่อวาน" เพราะถือว่าร้านเปิดแล้ว (office.html:734, 743-747)
>
> ⚠️ **หลังกดเปิดแล้ว แก้รหัส วันเปิด และสาขาภาษีในแอปไม่ได้**: ปุ่ม "➕ เพิ่มสินค้า/ทำต่อ" จะเริ่มที่ขั้น ② และย้อนกลับไปขั้น ① ไม่ได้ (admin.html:2361, 2384, 2405) · แก้ได้แค่ชื่อกับชื่อสั้น ที่ P&L → ตั้งค่า → การ์ด "สาขา" → แก้ไขชื่อ (jjmk-pnl.html:7366, 1603-1656)

**การเปิดสาขาทำอะไรให้ระบบที่เกี่ยวกับเครื่องสแกนบ้าง**: ทำแค่เพิ่มสาขา 3 ลงทะเบียน `pnl_branches` แล้วแต่ละแอปจะอ่านทะเบียนนี้เอง (รายละเอียดอยู่ในตาราง "สาขาใหม่: ส่วนไหนรองรับแล้ว" ด้านล่าง)

**การเปิดสาขาไม่ได้ทำสิ่งเหล่านี้**:
- ไม่สร้างพนักงาน ไม่สร้างหรือผูกเครื่องสแกน · เช็กลิสต์หลังเปิดสาขาบอกให้ทำเองใน JJ Payroll (admin.html:2813) ซึ่งคือขั้น E และ G
- ไม่ Deploy Worker ใน Cloudflare (ขั้น C) · เช็กลิสต์หลังเปิดสาขาไม่ได้เตือนเรื่องนี้

> ⚠️ **ตรวจรหัสและชื่อสาขา 3 ให้ถูกก่อนเพิ่มพนักงานหรือผูกเครื่อง**: ปุ่ม ↩️ ยกเลิกสาขาที่เปิดผิด จะใช้ไม่ได้ทันทีที่มีพนักงานหรือเครื่องสแกนที่ตั้งสาขาเป็นรหัสนี้ (branches.sql:369-377)

หลังเปิดสาขา ให้**โหลดหน้าแอปเงินเดือนใหม่** (กดรีโหลดของเบราว์เซอร์ หรือลากหน้าลง ถ้าแอปถามรหัสก็ใส่ใหม่) ทุกเครื่องที่เปิดค้างไว้ เพราะแอปอ่านทะเบียนสาขาแค่ตอนเปิดแอป (`startApp` payroll.html:7681-7683) · **ปุ่ม "🔄 รีเฟรชข้อมูล" ในแอปไม่ช่วย** เพราะปุ่มนี้เรียก `refreshAll` → `loadAll` (payroll.html:798, 2721, 2584) ซึ่งไม่อ่านทะเบียนสาขาและไม่เรียก `brSync` · ถ้าโหลดใหม่แล้วยังไม่มี ให้รอสักครู่แล้วโหลดใหม่อีกครั้ง (แอปรอทะเบียนแค่ 4 วินาที ไม่ทันก็ใช้รายชื่อที่จำไว้ในเครื่อง payroll.html:7681)

### B2. ตั้งสิทธิ์ผู้จัดการสาขา 3 (เจ้าของทำ · หลัง B ก่อน E)

ข้ามได้ถ้าเจ้าของ (admin/owner) จะเพิ่มพนักงานและผูกเครื่องเอง · ถ้าให้ผู้จัดการสาขา 3 ทำ:
1. JJ Access → **👥 ผู้ใช้ & สิทธิ์** → เลือกคน → กล่อง **JJ Payroll** (admin.html:816)
2. แถว **"🏪 เห็นเฉพาะพนักงานสาขา"** → ติ๊กสาขา 3 (admin.html:881, 1789-1796) · ถ้าติ๊กครบทุกสาขา ระบบจะไม่เก็บการจำกัดสาขาเลย = เห็นทุกสาขา (admin.html:1829-1832)
3. เปิดสิทธิ์ **"เพิ่ม"** ที่หน้า **พนักงาน** ถ้าจะให้เพิ่มคน · เปิด **"แก้"** ที่หน้า **ตั้งค่า** ถ้าจะให้ผูกเครื่องเอง (payroll.html:7598)
- ถ้าไม่ติ๊กสาขา 3 ให้ผู้จัดการที่ถูกจำกัดสาขาอยู่แล้ว จะบันทึกพนักงานสาขา 3 ไม่ได้ ขึ้นว่า "❌ เลือกสาขาสังกัดที่คุณดูแลก่อน" (payroll.html:4697) และไม่เห็นสาขา 3 ในตัวเลือก (payroll.html:2359-2364)
- ถ้าผู้จัดการเห็นป้าย "🔒 สิทธิ์: ไม่มีสาขาที่เปิดให้ดู" (payroll.html:2368) หรือการ์ด 📟 ขึ้น "ไม่มีสาขาที่ดูแล" = แอปของเขายังอ่านทะเบียนสาขาไม่ทัน (สิทธิ์ที่มีแต่รหัสที่แอปยังไม่รู้จัก จะกลายเป็นไม่เห็นอะไร payroll.html:2334-2337) → **โหลดหน้าใหม่** (ไม่ใช่ปุ่ม 🔄) ถ้ายังขึ้นอยู่ ให้ตรวจข้อ 2 อีกครั้ง

### E. เพิ่มพนักงานสาขา 3 ในแอปเงินเดือน (ทำใกล้วันลงหน้าที่สุด แต่ต้องก่อนชี้เครื่องมาที่ Worker)

> - สรุป LINE 21:00 ทุกคืนจะมีข้อความ "📋 สรุปวันนี้ · สาขา 3" ขึ้นทุกคนที่ยังไม่มีสแกนเป็น "❌ ไม่มา" (คนที่ตั้งวันหยุดประจำวันนั้นขึ้นเป็น 🛌) และยอด "รวมทุกสาขา · ไม่มา" ก็นับรวมไปด้วย (worker.js:544-556, 586-588, 593)

**พนักงานใหม่**: แอปเงินเดือน → 👥 พนักงาน → **＋ เพิ่มพนักงาน** (payroll.html:834) → กรอกชื่อเล่น, **รหัสพนักงาน (จากเครื่องสแกน)** (payroll.html:1838), **สาขาสังกัด = ชื่อสาขา 3 (รหัส)** (แอปเติมตัวเลือกนี้ให้จากทะเบียน payroll.html:7658) → บันทึก
- **ต้องเลือกสาขา 3 เองทุกครั้ง ห้ามเลือก "– อัตโนมัติตามแผนก –"** (payroll.html:1861): สาขาที่ได้จากตัวเลือกนี้มาจาก trigger ในฐานข้อมูลที่เดาสาขาจากแผนก ซึ่งไม่มีโค้ดใน repo และอาจใส่เป็น JJLP ได้ (docs/branches.md:32 · P-CLAUDE:46) · ทุกครั้งที่เปลี่ยนแผนกของคนสาขา 3 ให้กลับมาดูช่องสาขาอีกครั้ง
- **ออกรหัสจากแอปที่เดียว** ห้ามใช้ ID ที่เครื่องเสนอให้: แต่ละเครื่องนับเลขของตัวเอง ถ้ามีหลายเครื่อง รหัสอาจชนกับพนักงานสาขาอื่น แล้วเวลาสแกนจะไปลงที่คนนั้นแบบเงียบ ๆ (worker.js:875-880)
  - **ฟอร์มไม่ได้ออกเลขให้** เจ้าของต้องตั้งเลขเอง ถ้าเว้นช่องรหัสไว้ แอปจะตั้งเป็น `M` ตามด้วยเลขเวลา (payroll.html:4683) ซึ่ง ZK บางรุ่นพิมพ์ไม่ได้
  - **วิธีตั้งเลข**: ใช้ตัวเลขล้วน ไม่ขึ้นต้นด้วย 0 ยาวไม่เกินที่เครื่องรับ (เช็กลิสต์ซื้อเครื่องข้อ 5) และ**กันช่วงเลขไว้ให้สาขา 3 โดยเฉพาะ** (เช่น 3001, 3002, 3003 … ตกลงช่วงเลขกับเจ้าของก่อน) แล้วตรวจก่อนบันทึกทุกคนด้วย SQL ในข้อ 6 "รับพนักงานใหม่หลังมีหลายเครื่อง (รวมสาขา 3)"
  - ดูว่าช่วงเลขที่จะใช้มีใครใช้ไปแล้วบ้าง (อ่านอย่างเดียว · ตัวอย่างนี้ดูเลข 4 หลักที่ขึ้นต้นด้วย 3):

```sql
select code, nick, branch, active
```

  - **การเปลี่ยนสาขาสังกัดมีผลกับทิปทั้งงวด**: ทิปคิดจากสาขาสังกัด "ตอนที่คิด" ไม่ได้ดูว่าแต่ละวันทำที่สาขาไหน (payroll.html:3731 · ตัวหาร 3721-3726 · รายชื่ออัตโนมัติ 3747-3749) ถ้าย้ายกลางงวด คนนั้นจะ**หลุดจากทิปของสาขาเดิมทั้งงวด** และได้ส่วนแบ่งทิปของสาขา 3 ทั้งงวด (ถ้าสาขา 3 มีทิปงวดนั้น) แม้จะทำที่สาขาเดิมเกือบทั้งงวด · คิดใหม่ทุกครั้งที่เปิดดู งวดเก่าที่เปิดดูย้อนหลังก็เปลี่ยนตามสาขาปัจจุบันด้วย
  - ทิปแบบ "👥 เลือกคน" ของสาขาเดิมก็ใส่คนที่ย้ายออกไปแล้วไม่ได้ ระบบตัดคนที่สาขาสังกัดไม่ตรงออก (payroll.html:3736-3737)
  - **แนะนำ**: ย้ายตอนต้นงวด (วันที่ 26) ถ้าทำได้ · ถ้าต้องย้ายกลางงวด **ถามเจ้าของก่อน**ว่าจะแบ่งทิปงวดนั้นอย่างไร (เช่น ใส่ส่วนที่ควรได้จากสาขาเดิมเป็นรายการเพิ่มเงินเอง) · ถ้ายังต้องใช้สลิปงวดก่อน ให้พิมพ์หรือบันทึกไว้ก่อนย้าย
- **ย้ายจาก OFFICE มาสาขา 3: ถามเจ้าของหรือ Claude ก่อนเปลี่ยน** เพราะรอบงวดจะเปลี่ยนจาก 1→สิ้นเดือน เป็น 26→25 (P-CLAUDE:49-52) และจะไม่ได้รับการยกเว้นกฎห้ามหยุดแบบ OFFICE อีก (payroll.html:3292)
- วันที่เคยทำงานที่สาขาเดิมในงวดเดียวกันจะแสดงเป็น "ข้ามสาขา" ในรายงาน ป้ายนี้**เป็นแค่การแสดงผล ไม่มีผลกับยอดเงิน** (payroll.html:3315-3317) · แต่ทิปไม่ได้ดูป้ายนี้ (ดูข้อทิปด้านบน)
- ผู้ใช้ในเครื่องสาขาเดิม: เก็บไว้ได้ถ้ายังต้องไปช่วยสาขาเดิม (สแกนที่นั่นจะนับเป็นข้ามสาขา) หรือลบออกจากเครื่องเดิมก็ได้ ไม่กระทบข้อมูลในระบบ เพราะ Worker ไม่ซิงก์รายชื่อกับเครื่อง (worker.js:82-92)

ตรวจรายชื่อสาขา 3 (อ่านอย่างเดียว · ใช้พิมพ์ให้ช่างตอนลงหน้าได้ด้วย):

```sql
-- พนักงานสาขา 3 (อ่านอย่างเดียว)
select code      as "รหัส (ใส่ในเครื่อง)",
       nick      as "ชื่อเล่น",
       full_name as "ชื่อ-นามสกุล",
       dept      as "แผนก",
       branch    as "สาขา"
  from employees
 where active and branch = 'ใส่รหัสสาขา 3 ตรงนี้'
 order by nick;
-- คนสาขา 3 ต้องไม่อยู่ในรายการนี้ (คนที่ยังไม่มีสาขา · อ่านอย่างเดียว)
select id, code, nick, dept, branch
  from employees
 where active and (branch is null or branch = '')
 order by id desc;
```

### ระบบรับได้ 2 วิธีส่งข้อมูล ไม่ได้ดูยี่ห้อ (worker.js:7-11, 70, 78-92)

| วิธีส่งข้อมูล | ADMS / iclock (เมนู "Cloud Server Setting") | ISAPI "HTTP Listening" แบบ JSON |

"รุ่นที่มีชื่อในโค้ด" เป็นแค่คอมเมนต์กับข้อความหน้าแรกของ Worker **ไม่ได้แปลว่าร้านใช้รุ่นนั้นอยู่จริง และไม่มีหลักฐานในโค้ดว่าเคยทดสอบกับรุ่นนั้น** (คอมเมนต์ worker.js:63 เขียนว่าเก็บ log "ไว้ดูของจริงตอนเครื่องมาถึง" แปลว่าตอนเขียนยังไม่มีเครื่องจริง) ·

### เครื่องที่ใช้อยู่ตอนนี้เป็นยี่ห้อหรือรุ่นอะไร — ยังไม่มีบันทึกไว้

ค้นแล้วใน worker.js · P-CLAUDE:14 · MOVE-CHECKLIST.md:33 · JJ-Payroll-Summary.md:16 · คู่มือ PDF หน้า 3 และสไลด์หน้า 3–4 ทุกที่เขียนแค่ "ZKTeco / Hikvision" กับ "ลาดพร้าวและรัชดามีเครื่องของตัวเอง ครัวกลางใช้เครื่องลาดพร้าว" **ไม่มีที่ไหนบอกยี่ห้อ รุ่น หรือ SN ของเครื่องแต่ละสาขา** จึงต้องดูเองก่อนไปซื้อ:

1. **ดูที่ตัวเครื่องจริง** ที่ลาดพร้าวและรัชดา: โลโก้หน้าเครื่อง สติกเกอร์รุ่นหลังหรือใต้เครื่อง หรือเมนูข้อมูลเครื่องบนจอ ถ่ายรูปเก็บไว้แล้วเอาไปให้ร้านดู
2. **ดูจากตาราง `devices` (วิธีหลัก ไม่ต้องพึ่ง `device_log`)**: เครื่องแบบ ZKTeco ติดต่อเข้ามาเองทุกประมาณ 30 วินาทีแม้ไม่มีคนสแกน `last_seen` จึงขยับตลอด (worker.js:42, 88-91) ส่วนแบบ Hikvision ขยับเฉพาะตอนมีคนสแกนสำเร็จ (worker.js:799) · SN ของ Hikvision คือ deviceID หรือ MAC หรือ IP (worker.js:782) ส่วน ZKTeco คือ Serial Number ที่เครื่องส่งมาเอง (worker.js:52) · **รันตอนที่ไม่มีใครสแกนมาอย่างน้อย 10 นาที และเครื่องเปิดอยู่** (เช่น กลางกะ หรือหลังปิดร้านถ้าไม่ได้ปิดเครื่อง) · อ่านอย่างเดียว:

```sql
-- เดายี่ห้อจาก devices อย่างเดียว (อ่านอย่างเดียว)
select sn     as "SN",
       branch as "สาขา",
       last_seen::timestamptz at time zone 'Asia/Bangkok' as "ติดต่อล่าสุด (เวลาไทย)",
       now() - last_seen::timestamptz                     as "ผ่านมาแล้ว",
       case
         when sn = 'HIK' then 'Hikvision (ไม่ส่งรหัสเครื่อง)'
         when sn ~* '^([0-9a-f]{2}[:-]){5}[0-9a-f]{2}$' then 'SN เป็น MAC → Hikvision'
         when sn ~ '^[0-9]{1,3}(\.[0-9]{1,3}){3}$' then 'SN เป็น IP → Hikvision'
         when now() - last_seen::timestamptz < interval '5 minutes' then 'ติดต่อเองตลอด → น่าจะ ZKTeco'
         else 'ยังบอกไม่ได้ — ดูข้อ 1 และข้อ 3'
       end as "เดายี่ห้อ"
  from devices
 where sn <> 'DEBUG-TEST'
 order by last_seen desc nulls last;
```

3. **ดูจากวิธีที่เครื่องติดต่อเข้ามา** (ใช้ยืนยันข้อ 2 · Supabase → SQL Editor · อ่านอย่างเดียว): ZKTeco ติดต่อผ่าน `/iclock/cdata` และ `/iclock/getrequest` พร้อม SN (worker.js:52, 77-92) ส่วน Hikvision ติดต่อผ่าน `/hik` (worker.js:69-75)

```sql
-- เครื่องแต่ละเครื่องเป็นยี่ห้อไหน + ผูกสาขาอะไร (อ่านอย่างเดียว · ตาราง device_log ใหญ่ อาจรอหลายวินาที)
with zk as (
  select distinct sn
    from device_log
   where sn <> '' and (path like '%/cdata%' or path like '%/getrequest%')
)
select d.sn     as "SN",
       d.branch as "สาขา",
       d.name   as "ชื่อเรียก",
       case when zk.sn is not null then 'ZKTeco (ADMS)'
            else 'ไม่เคยติดต่อแบบ ZKTeco → น่าจะ Hikvision' end as "ยี่ห้อ (ดูจากวิธีติดต่อ)",
       d.last_seen::timestamptz at time zone 'Asia/Bangkok'          as "ติดต่อล่าสุด (เวลาไทย)"
  from devices d
  left join zk on zk.sn = d.sn
 where d.sn <> 'DEBUG-TEST'
 order by d.last_seen desc nulls last;
```

ผลข้อ 2 และ 3 เป็นการเดา: ถ้า `device_log` ถูกลบหรือหยุดบันทึกไปช่วงหนึ่ง (docs/access.md:90) เครื่อง ZK อาจขึ้นว่า "น่าจะ Hikvision" ในข้อ 3 ได้ · ถ้าเครื่องปิดอยู่ ข้อ 2 จะดูไม่ออก · ให้ยืนยันกับตัวเครื่องจริง (ข้อ 1) ทุกครั้ง

### คำแนะนำ

1. **ทางปลอดภัยที่สุด: ซื้อยี่ห้อและรุ่นเดียวกับเครื่องที่ส่งข้อมูลเข้าระบบนี้ได้อยู่แล้ว** เพราะตั้งค่าได้เหมือนเดิมทุกช่อง ช่างเคยตั้งมาแล้ว และย้ายผู้ใช้หรือใบหน้าระหว่างเครื่องยี่ห้อเดียวกันได้ง่ายกว่า (ข้ามยี่ห้อส่วนใหญ่ย้ายไม่ได้)
2. ถ้ารุ่นเดิมเลิกขายแล้ว ให้เลือกยี่ห้อเดิมรุ่นที่ร้านตอบเช็กลิสต์ข้างล่างผ่านทุกข้อ · ถ้าต้องเลือกระหว่าง 2 ยี่ห้อ จากโค้ดแล้ว ZKTeco ตรวจง่ายกว่า (เห็นว่าเครื่องต่อติดโดยไม่ต้องสแกน และได้ SN จริง) ส่วน Hikvision มีค่าที่ต้องตั้งให้ถูกมากกว่า (HTTPS + JSON + ส่งเฉพาะเหตุการณ์ยืนยันตัวตน + IP ไม่ซ้ำ)
3. ถ้าร้านเสนอยี่ห้ออื่น หรือ ZKTeco/Hikvision ที่ไม่มีเมนูตามตารางด้านบน **อย่าเพิ่งซื้อ** แจ้ง Claude ก่อน

### เช็กลิสต์ถามร้านขายก่อนจ่ายเงิน (ขอคำตอบทางแชทหรือเป็นลายลักษณ์อักษร)

ข้อ 1–5 ถ้าร้านตอบว่า "ไม่ได้" หรือ "ไม่แน่ใจ" ข้อใดข้อหนึ่ง = **อย่าเพิ่งซื้อ** แจ้ง Claude ก่อน

7. ตั้งเขตเวลา **GMT+7** และให้นาฬิกาซิงก์อัตโนมัติ (NTP) ได้ไหม
8. **ลบเฉพาะบันทึกการเข้างาน** โดยไม่ลบผู้ใช้และใบหน้าได้ไหม (เมนูชื่ออะไร)

```sql
-- เครื่องสแกนที่ระบบรู้จัก (อ่านอย่างเดียว)
-- ค่า last_seen ในตารางเป็นเวลา UTC (ช้ากว่าเวลาไทย 7 ชม.) ให้ดูคอลัมน์ "เวลาไทย" แทน
```

   - เครื่องเดิมเป็น ZKTeco: ต้องเห็นแถว path `/iclock/getrequest` ภายในไม่กี่นาทีล่าสุด (เครื่องถามทุก 30 วินาที `Delay=30` worker.js:42) · เครื่องเดิมเป็น Hikvision: ต้องเห็นแถว path `/hik` ตรงกับเวลาที่มีคนสแกนล่าสุด
   - ไม่เห็นแถวใหม่ = **แจ้ง Claude ก่อนติดตั้ง**
5. พิมพ์รายชื่อพร้อมรหัสให้ช่าง (อ่านอย่างเดียว · ถ้าจะเอาสาขาเดียวให้เติม `and branch = 'JJRD'` หรือรหัสสาขา 3 ก่อน `order by`):

```sql
-- รหัสที่ต้องใส่ในเครื่องใหม่ (อ่านอย่างเดียว)
select code      as "รหัส (ใส่ในเครื่อง)",
       nick      as "ชื่อเล่น",
       full_name as "ชื่อ-นามสกุล",
       branch    as "สาขา",
       case
         when code is null or btrim(code) = ''
           then '⚠️ ไม่มีรหัส — ตั้งในแอปก่อน'
         when code ~ '^[[:space:]]|[[:space:]]$'
           or position(chr(160) in code) > 0
           or position(chr(65279) in code) > 0
           then '⚠️ มีช่องว่าง/อักขระซ่อน — แจ้ง Claude'
         when code !~ '^[0-9]+$'
           then '⚠️ ไม่ใช่ตัวเลขล้วน — ZK บางรุ่นใส่ไม่ได้'
         when length(code) >= 10
           then 'ℹ️ ยาว ' || length(code) || ' หลัก — เช็คว่าเครื่องใหม่รับได้'
       end as "เตือน"
  from employees
 where active
 order by branch, nick;
```

   - **⚠️ มีช่องว่าง/อักขระซ่อน**: Worker ตัดช่องว่าง แท็บ ขึ้นบรรทัด และ NBSP ออกจากรหัสที่เครื่องส่งมา (`.trim()` worker.js:774, 855) แล้วเทียบกับ `employees.code` แบบตรงตัว (worker.js:877-879) คนนั้นจะถูกสร้างซ้ำทันทีที่สแกน แจ้ง Claude ให้เตรียมวิธีแก้ก่อน
   - **⚠️ ไม่มีรหัส / ไม่ใช่ตัวเลขล้วน**: คนที่เพิ่มในแอปโดยไม่กรอกรหัส ระบบตั้งรหัสให้เป็น `M` ตามด้วยเลขเวลา เช่น `M1729340000000` (payroll.html:4683) ZK ที่รับ User ID เป็นตัวเลขล้วนหรือรับได้ไม่กี่หลักจะพิมพ์รหัสนี้ไม่ได้ ช่างก็จะตั้งเลขใหม่เอง แล้ว Worker จะสร้างพนักงานซ้ำ (worker.js:875-912) · **วิธีแก้ (ทำก่อนลงหน้า)**: เช็คว่ารหัสนั้นยังไม่มีเวลาสแกนเลย แล้วตั้งรหัสตัวเลขจริงในฟอร์ม ✎ หน้าพนักงาน ช่อง "รหัสพนักงาน (จากเครื่องสแกน)" (payroll.html:1838) ได้อย่างปลอดภัย เพราะไม่มีเวลาสแกนให้ตกค้าง (ข้อห้ามแก้รหัสในข้อ 6 ใช้กับคนที่มีสแกนแล้วเท่านั้น):

```sql
-- ต้องได้ 0 ก่อนเปลี่ยนรหัสในฟอร์ม ✎ (อ่านอย่างเดียว)
select count(*) as "จำนวนสแกน" from punches where emp_code = 'ใส่รหัสเดิมตรงนี้';
-- รหัสใหม่ต้องยังไม่มีใครใช้: ต้องได้ 0 แถว (อ่านอย่างเดียว)
select code, nick, active from employees where code = 'ใส่รหัสใหม่ตรงนี้';
```

6. **จด id ล่าสุดของพนักงานไว้** ใช้เช็คพนักงานที่เกิดใหม่หลังติดตั้งในข้อ 4-6 (อ่านอย่างเดียว · ถ้าเพิ่มพนักงานสาขา 3 ในแอปตามขั้น E แล้ว ให้จด**หลัง**เพิ่มเสร็จ):

```sql
select max(id) as "id ล่าสุด (จดไว้)", current_date as "วันที่จด" from employees;
```

## 1. ตั้งเครื่อง + ลงหน้าพนักงาน (ตอนเครื่อง**ยังไม่ได้**ชี้มาที่ Worker)

**ทำข้อนี้ให้เสร็จทั้งหมดก่อนข้อ 2** ระหว่างนี้ช่องปลายทางยังว่าง (ZK: ยังไม่ใส่ Server Address · Hikvision: ยังไม่เปิด HTTP Listening) หรือถอดสาย LAN ไว้ก็ได้ จะลองสแกนกี่ครั้งก็ไม่เข้าระบบเงินเดือน

> **ทำไม**: พอเครื่องชี้มาที่ Worker แล้ว ทุกสแกนที่ผ่านเป็นเวลาเข้างานจริงของรหัสนั้น ZK บันทึกทุกบรรทัด ATTLOG (worker.js:85, 849-871) Hikvision บันทึกทุกเหตุการณ์ที่มีรหัส (worker.js:769-800) กันซ้ำได้แค่สแกนในนาทีเดียวกัน ถ้าพนักงานลองสแกนหลังลงหน้า:
> - วันที่มีสแกนนับเป็นวันทำงาน `days = ss.length` (payroll.html:3222) คนรายวันได้ค่าแรงเพิ่ม `days * rate` (payroll.html:3341) และวันนั้นไม่ถูกนับว่าหยุดวันห้ามหยุด (payroll.html:3308)
> - สแกนครั้งเดียวในวันที่ไม่ได้ทำงาน = ปรับลืมตอก 200 (payroll.html:3328 · P-CLAUDE:58)
> - สแกน 2 ครั้งห่างกันนอกเวลากะ = กลายเป็นคู่เข้า-ออก แล้วคิดสาย/ออกก่อนหลายร้อยนาที × 1.5 บาท (payroll.html:3138-3150, 3326 · P-CLAUDE:57)
> - ลองสแกนก่อนเข้ากะจริง: ระบบใช้สแกนแรก/สุดท้ายเลือกกะ (payroll.html:3038-3046 · worker.js:297-312) จึงจับกะ สาย และออกก่อนผิดได้ · Parttime นับ in = สแกนแรก out = สแกนสุดท้าย (payroll.html:3102-3105)
> - จอลูกค้า KPI นับคนที่ยังอยู่จากจำนวนสแกนคี่ (kpi.sql:278-290) สแกนเกิน 1 ครั้ง ชื่อจะหายหรือค้างผิดทั้งกะ · รายงาน LINE 11:01/15:01/18:01/21:00 นับว่าเข้างานแล้ว (worker.js:486-494, 544-550) · เช้าวันรุ่งขึ้นออฟฟิศ AI ขึ้นแดง "สแกนครั้งเดียว" (office.html:797-813)

### 1.1 ตั้งเครือข่ายและเวลา

| เมนูบนเครื่อง | ค่าที่ต้องใส่ |
|---|---|
| IP address | IP คงที่ ที่ไม่ซ้ำกับเครื่องอื่นในร้าน (ถ้าเป็น Hikvision ให้ไม่ซ้ำกับ Hikvision ทุกเครื่องทุกสาขาด้วย ดูข้อ 2B) |
| Gateway | IP ของเราเตอร์ |
| **DNS** | `1.1.1.1` / `8.8.8.8` หรือ IP ของเราเตอร์ · **ห้ามเว้นว่าง** ช่องนี้มักว่างหลังเปลี่ยนเป็น IP คงที่ เครื่องจะหาโดเมน Worker ไม่เจอ ไม่ส่งอะไรเลย ตาราง `devices`/`device_log` ก็ไม่มีแถว และ NTP ก็ใช้ไม่ได้ |
| วันที่/เวลา | เขตเวลา **GMT+7 / (GMT+07:00) Bangkok** + นาฬิกาตรงกับเวลาจริง (เปิด NTP / ซิงก์เวลาอัตโนมัติถ้ามี) |

- **เขตเวลาสำคัญมาก (Hikvision)**: Worker แปลงเวลาให้เฉพาะเวลาที่ลงท้ายด้วย `Z` ส่วนเวลาที่มี offset อื่นจะใช้ตัวเลขตามที่เครื่องเขียนมาเลย ถ้าเครื่องตั้งเป็น `+00:00` เวลาจะคลาด 7 ชม. ถ้าตั้งเป็น `+08:00` จะคลาด 1 ชม. และไม่มีอะไรเตือน (worker.js:824-833)

### 1.2 ลงหน้าพนักงาน

**กฎข้อเดียวที่ห้ามพลาด: ZKTeco "User ID / PIN" หรือ Hikvision "Employee No." = `employees.code` ของคนนั้น ตรงทุกตัวอักษร รวมเลข 0 นำหน้า**
(Worker เทียบรหัสแบบตรงตัว worker.js:875-879 · แอปก็เทียบแบบตรงตัว payroll.html:3092)

- เอารหัสจาก SQL ข้อ 0 ข้อ 5 (ทั้งร้าน) หรือ SQL ขั้น E (สาขา 3) หรือในแอปทีละคน: หน้าพนักงาน → ✎ ช่อง **"รหัสพนักงาน (จากเครื่องสแกน)"** (payroll.html:1838) หรือแท็บข้อมูลส่วนตัว บรรทัด **"รหัสเครื่องสแกน"** (payroll.html:5154)
- **ใส่ชื่อเล่นในช่องชื่อของเครื่อง** ให้จอขึ้นชื่อตอนสแกน
- **ห้ามใช้ ID ที่เครื่องเสนอให้อัตโนมัติ** ต้องพิมพ์รหัสจากรายชื่อเท่านั้น
- **ย้ายใบหน้า+ผู้ใช้จากเครื่องเดิม** (USB / backup / ซอฟต์แวร์ผู้ผลิต) ให้ทำในข้อนี้ ก่อนชี้มาที่ Worker เพราะประวัติสแกนเก่าอาจติดมาด้วย (ล้างในข้อ 2) · ระบบนี้ไม่ซิงก์ใบหน้าหรือรายชื่อระหว่างเครื่อง และ Worker ไม่ส่งรายชื่อหรือใบหน้าไปให้เครื่อง (ตอบ `/getrequest` ด้วย `OK` เปล่า และทิ้ง USERINFO/FACE ที่เครื่องส่งขึ้นมา worker.js:82-92) · ข้ามยี่ห้อส่วนใหญ่ย้ายไม่ได้ ให้ถามผู้ขาย
- **รหัสยาว**: บางคนใช้รหัส 10 หลัก (เช่นที่จดไว้ใน P-CLAUDE:235) เช็คก่อนว่าเครื่องใหม่รับความยาวนี้ได้ ถ้าเครื่องตัดหลัก รหัสจะไม่ตรง
- **ช่อง ☑ "เพิ่มหน้าในเครื่องสแกนแล้ว" มีช่องเดียวต่อคน** ไม่ได้แยกว่าเครื่องไหน (payroll.html:4991) ให้ใช้รายชื่อที่พิมพ์จาก SQL ติ๊กเองว่าใครลงหน้าเครื่องใหม่แล้ว
- คนที่ยังไม่ได้ลงหน้าในเครื่องใหม่ สแกนไม่ผ่าน = ไม่มีเวลาเข้างาน ให้ใช้เครื่องเดิมไปก่อนจนกว่าจะลงหน้าเสร็จ (สาขา 3 ไม่มีเครื่องเดิม ให้ลงหน้าทุกคนให้เสร็จก่อนวันเปิดใช้)

### 1.3 ตรวจทุกคนที่ลงหน้า (ยังไม่ชี้มาที่ Worker จึงลองสแกนได้)

1. ให้แต่ละคนลองสแกน แล้ว**ให้เจ้าตัวยืนยันว่าชื่อบนจอเป็นชื่อตัวเอง**
2. ถ้าเครื่อง export รายชื่อผู้ใช้ (ID + ชื่อ) ได้ ให้ export มาเทียบกับรายชื่อจาก SQL ทีละบรรทัด

> **ทำไมต้องตรวจทุกคน**: Worker สร้างพนักงานใหม่เฉพาะตอนที่รหัสยังไม่มีในตาราง (worker.js:877-880) ถ้ารหัสที่พิมพ์ไปตรงกับรหัสของ**พนักงานอีกคน**ที่มีอยู่แล้ว (พิมพ์ผิดหลัก หรือสลับรหัสสองคนที่ชื่อเล่นซ้ำกัน ซึ่งมีจริง เช่น ลิลลี่ 2 คน · น้ำฝน 2 คน · NANG PUT ซ้ำ 3 ใน P-CLAUDE:235) เวลาสแกนจะไปลงที่อีกคนแบบเงียบ ๆ ไม่มีแถวพนักงานใหม่ให้เห็น `/report/check` ก็ดูปกติ คนจริงดูเหมือนขาดงานและอาจโดนหักวันห้ามหยุด (payroll.html:3328-3334) อีกคนได้วันทำงานหรือปรับลืมตอกเพิ่ม

### ถ้ารหัสไม่ตรง ระบบจะทำแบบนี้ (หลังชี้มาที่ Worker แล้ว)

- **รหัสยังไม่มีในระบบ → สร้างพนักงานใหม่ให้ทันที**: รหัสตามที่สแกน · ชื่อเล่นเป็นตัวเลขรหัส (ZKTeco) หรือชื่อที่พิมพ์ในเครื่อง (Hikvision) · **รายเดือน 12,000** · ไม่มีสาขา · วันเริ่มงานเป็นวันที่สแกนครั้งแรก (worker.js:875-912)

## 3. ผูกเครื่องกับสาขา

ระบบรู้ว่าเครื่องอยู่สาขาไหนจากช่อง `devices.branch` (แอป payroll.html:2594, 2650 · Worker worker.js:241, 258-260) ค่านี้ต้องเป็น**รหัสสาขา** `JJLP` / `JJRD` / `JJCK` / `OFFICE` / รหัสสาขาใหม่ ห้ามเป็นชื่อไทย

### วิธีหลัก: การ์ด "📟 เครื่องสแกน → สาขา" ในแอปเงินเดือน (เพิ่ม 2026-10-15)

- **อยู่ที่ไหน**: แอปเงินเดือน → เมนู **⚙️ ตั้งค่า** (payroll.html:788) → การ์ด "📟 เครื่องสแกน → สาขา" (payroll.html:1222-1224) · แอปโหลดรายชื่อเครื่องใหม่ทุกครั้งที่เปิดหน้านี้ (payroll.html:2905, 7590)
- **ใครทำได้**: ต้องมีสิทธิ์ "แก้" หน้าตั้งค่า (payroll.html:7598) · admin/owner ทำได้เสมอ · ผู้จัดการที่ถูกจำกัดสาขา (`_br`) เลือกได้เฉพาะสาขาที่ตัวเองดูแล (payroll.html:2341) · แทนช่องเลือก การ์ดอาจขึ้นได้ 2 ข้อความ (payroll.html:7606): "ไม่มีสิทธิ์แก้หน้าตั้งค่า" = บัญชีนี้ไม่มีสิทธิ์ "แก้" · "**ไม่มีสาขาที่ดูแล**" = มีสิทธิ์แก้ แต่รายการสาขาที่ดูแลว่าง (payroll.html:7598) เช่น ผู้จัดการที่ตั้งสิทธิ์ไว้แค่สาขา 3 แต่แอปยังอ่านทะเบียนสาขาไม่ได้ (payroll.html:2334-2337) → โหลดหน้าใหม่ ถ้ายังขึ้น ให้ตรวจสิทธิ์ตามขั้น B2
- **เห็นเครื่องไหนบ้าง** (payroll.html:7594-7610):
  - **เครื่องที่ยังไม่ผูกสาขา** ขึ้นด้านบนพร้อมกล่อง "⚠️ มี N เครื่องที่ยังไม่ผูกสาขา" · แต่ละแถวมี SN · ชื่อเรียก · เวลา "ส่งข้อมูลล่าสุด" · ช่อง "— เลือกสาขาของเครื่องนี้ —" · นับรวมเครื่องที่ช่องสาขาเป็นค่าที่แอปไม่รู้จัก (เช่น ชื่อไทย จะขึ้นว่า "สาขาในตาราง ... ไม่รู้จัก") · **ทุกคนที่เปิดการ์ดเห็นเครื่องที่ยังไม่ผูกครบทุกเครื่อง** รวมผู้จัดการรายสาขาด้วย
  - **เครื่องที่ผูกแล้ว** อยู่ในหัวข้อพับ "เครื่องที่ผูกสาขาแล้ว N เครื่อง" (ผู้จัดการรายสาขาเห็นเฉพาะสาขาตัวเอง) **ดูได้อย่างเดียว เปลี่ยนสาขาในแอปไม่ได้** ถ้าผูกผิดต้องแก้ด้วย SQL ด้านล่าง
  - ทุกเครื่องผูกครบ = "✓ เครื่องสแกนทุกเครื่องผูกสาขาแล้ว (N เครื่อง)" · **แต่ถ้ามีแถว `DEBUG-TEST` อยู่** (เกิดจากหน้า `/debug`) แถวนี้ไม่มีสาขา จึงถูกนับในกล่อง "⚠️ มี N เครื่องที่ยังไม่ผูกสาขา" ตลอด และจะไม่ขึ้น ✓ เลย (payroll.html:7594-7595, 7599-7608) · ตอนตรวจเครื่องใหม่ให้ดู SN ทีละแถว อย่ารอ ✓
- **วิธีทำ**: หาแถวที่ SN ตรงกับเครื่องใหม่ (เวลา "ส่งข้อมูลล่าสุด" ต้องเพิ่งเกิด) → เลือกสาขา → กด OK ที่หน้าต่างยืนยัน "ผูกเครื่องสแกน ... กับสาขา...? เวลาสแกนจากเครื่องนี้ (รวมที่สแกนไปแล้ว) จะนับเป็นสาขานี้" (payroll.html:7615)
- **ผูกแล้วเกิดอะไร** (payroll.html:7617-7622):
  - บันทึก `devices.branch` แล้วขึ้น "📟 ผูกเครื่อง ... กับสาขา... แล้ว"
  - เครื่องที่กดจะคิดใหม่ทันที รวมสแกนย้อนหลังของเครื่องนั้น ไม่ต้องรีเฟรช · ผู้จัดการรายสาขาต้องกด 🔄 รีเฟรชข้อมูล (หรือโหลดหน้าใหม่) เพื่อเห็นพนักงานใหม่ของสาขา (payroll.html:7622, 2689) · มือถือหรือคอมเครื่องอื่นที่เปิดแอปค้างไว้ต้องกด 🔄 หรือโหลดหน้าใหม่ (แอปอ่าน `devices` ตอนเปิด payroll.html:2594)
  - Worker เห็นค่าใหม่ในรายงานรอบถัดไปทันที เพราะอ่าน `devices` ใหม่ทุกครั้งที่ทำรายงาน (worker.js:241)
  - ถูกจดในหน้า 🕘 ประวัติการทำรายการ ว่าใครผูก (ทุกการแก้ผ่าน `db.from` ถูกจดอัตโนมัติ payroll.html:2405-2455)
- **ระวัง**:
  - **ห้ามผูกแถว `DEBUG-TEST`** (เกิดจากการเปิดหน้า `/debug` worker.js:956) และ**แถว `HIK`** (Hikvision ที่ไม่ส่งทั้ง deviceID/MAC/IP ถ้ามีเครื่องอื่นตกมาเป็น `HIK` ด้วยจะปนกัน) ปล่อยค้างไว้ได้ ไม่มีผลกับเวลาสแกนหรือเงิน แต่ `DEBUG-TEST` ทำให้กล่องเตือนนับเกิน 1 เครื่องตลอด (ดูข้างบน) · **ถ้าจะลบแถวนี้ต้องถามเจ้าของก่อน** (ลบข้อมูลจริง) · เป็น `HIK` ให้แจ้ง Claude
  - ผู้จัดการสาขาอื่นก็เห็นเครื่องใหม่ของสาขา 3 ในรายการที่ยังไม่ผูก ถ้าเผลอเลือกเป็นสาขาตัวเอง ต้องใช้ SQL แก้ · แนะนำให้เจ้าของเป็นคนผูกเอง
  - ขึ้น "❌ ผูกเครื่องสแกนไม่สำเร็จ" (payroll.html:7619) = ฐานข้อมูลไม่ยอมให้แก้ หรือไม่มีแถวนี้แล้ว → ใช้ SQL สำรอง
  - **ไม่มีสาขา 3 ในช่องเลือก** = แอปยังไม่ได้อ่านทะเบียนสาขา หรือยังไม่ได้เปิดสาขา (เส้นทางสาขา 3 ขั้น A–B) หรือผู้จัดการไม่มีสิทธิ์สาขา 3 (ขั้น B2) → **โหลดหน้าใหม่** (รีโหลดของเบราว์เซอร์ หรือลากหน้าลง) · ปุ่ม 🔄 รีเฟรชข้อมูลไม่อ่านทะเบียนสาขา (payroll.html:2721)
  - เรื่อง**เครื่อง**ใช้ปุ่ม 🔄 ได้ (ปุ่มนี้โหลดตาราง `devices` ใหม่ payroll.html:2594) · เรื่อง**ทะเบียนสาขา** (สาขา 3 ไม่ขึ้น) ต้องโหลดหน้าใหม่
  - การ์ดตั้ง "ชื่อเรียก" ของเครื่องไม่ได้ ถ้าอยากตั้งชื่อใช้ SQL (ไม่บังคับ)

### ทางสำรอง: SQL ผูกสาขา (แก้ข้อมูลจริง 1 แถว ไม่ลบอะไร รันซ้ำได้)

ใช้เมื่อผูกในแอปไม่ได้ ต้องเปลี่ยนสาขาของเครื่องที่ผูกไปแล้ว หรืออยากตั้งชื่อเรียก

```sql
-- ผูกเครื่องกับสาขา: แก้เฉพาะแถวของ SN นี้
update devices
   set branch = 'ใส่รหัสสาขา 3 ตรงนี้',     -- รหัสอังกฤษเท่านั้น: รหัสสาขา 3 / JJLP / JJRD / JJCK / OFFICE
       name   = 'สาขา 3 เครื่องที่ 1'      -- ชื่อเรียก (ไม่บังคับ · แก้ตามจริงได้)
 where sn = 'ใส่ SN ของเครื่องใหม่ตรงนี้'
returning sn, branch, name, last_seen;
```

- **ดูผลที่ขึ้นมา (returning) ทุกครั้ง**: ช่อง `branch` ต้องเป็นรหัสสาขาที่ตั้งใจ ถ้าผิด (เช่น ลืมแก้ช่อง "ใส่รหัส…") ให้แก้แล้วรันใหม่ทันที ไม่งั้นคนสาขา 3 จะถูกนับเป็นข้ามสาขา และรายงาน LINE ไปขึ้นการ์ดสาขาอื่น (worker.js:258-260, 333-334 · payroll.html:2650, 3096-3097)
- ได้ **0 แถว** = SN ผิด หรือเครื่องยังไม่เคยต่อเข้ามา (Hikvision: ยังไม่มีใครสแกนสำเร็จ) ให้ไปหา SN จริงในข้อ 4 ก่อน
- **ถ้า SN เป็น `HIK` ห้ามผูกสาขา** ให้แจ้ง Claude
- ค่าที่ผูกไว้จะไม่หาย เพราะเวลาเครื่องรายงานตัว Worker อัปเดตแค่ `sn` กับ `last_seen` (worker.js:914-921)
- **ผูกด้วย SQL แล้วต้องรีเฟรชแอปเงินเดือนทุกเครื่อง** (กด 🔄 หรือโหลดหน้าใหม่) เพราะแอปอ่าน `devices` ตอนเปิดเท่านั้น และ realtime ฟังแค่สแกนใหม่ (payroll.html:2594, 7389-7400) · สแกนย้อนหลังจะถูกจัดสาขาใหม่ให้เอง
- สาขาของเครื่องใช้แค่บอก "ทำงานที่สาขาไหน / ข้ามสาขา" ในรายงาน **ไม่มีผลกับยอดเงิน** (payroll.html:3315-3317, 5947, 6857)

### อย่าใช้ secret `BRANCH_MAP` แทน

มีผลแค่กับรายงาน LINE แอปไม่ได้อ่าน (worker.js:258-264) · ต้องใส่เป็นรหัสสาขา ไม่ใช่ชื่อไทย เพราะโค้ดเทียบด้วยรหัส (worker.js:192-193, 335-336) ตัวอย่างในคอมเมนต์รุ่นปัจจุบันแก้เป็นรหัสแล้ว (worker.js:30-33) · ถ้าตั้ง `BRANCH_MAP` ไว้แล้ว ค่าใน `BRANCH_MAP` ของเครื่องเดียวกันต้องตรงกับใน `devices` เพราะ `BRANCH_MAP` จะทับค่าในตาราง

## 4. ทดสอบ (ทำทันทีหลังติดตั้ง)

**ทดสอบด้วยเวลาเข้า-ออกงานจริงเท่านั้น ไม่ต้องสแกนเพิ่ม** สแกนทดสอบเป็นข้อมูลจริงที่ใช้คิดเงิน (เหตุผลในข้อ 1) · **สาขาที่ยังไม่เปิด**: นัดติดตั้งให้ตรงกับวันที่พนักงานมาทำงานจริงก่อนเปิดร้าน (เตรียมร้าน/อบรม) แล้วใช้สแกนเข้า-ออกของวันนั้นทดสอบ อย่ารอวันเปิดร้าน (เส้นทางสาขา 3 ขั้น H)

1. **เช็คว่าต่อติดก่อนสแกน**:
   - **ZKTeco**: การ์ด 📟 ต้องมีเครื่องใหม่ และ "ส่งข้อมูลล่าสุด" เพิ่งเกิด · หรือรัน SQL ข้อ 0 ข้อ 3 ต้องเห็น SN เครื่องใหม่ และ "ผ่านมาแล้ว" ไม่กี่นาที (ค่า `last_seen` ดิบเป็น UTC ช้ากว่าเวลาไทย 7 ชม.)
   - **Hikvision**: หลังเปิด HTTP Listening ดู Supabase → Table Editor → `device_log` กรอง `path` = `/hik` ถ้ามีแถวใหม่ = เครื่องส่งมาถึง Worker แล้ว (Worker จดทุกคำขอก่อนแปลงข้อมูล worker.js:64, 70) · ไม่มีก็ยังไม่แปลว่าเสีย (บางเครื่องส่งเฉพาะตอนมีเหตุการณ์) ให้ไปขั้น 2 · การ์ด 📟 จะยังไม่มีเครื่องนี้จนกว่าจะมีคนสแกนสำเร็จ
2. **รอคนที่กำลังจะเข้ากะ** (ลงหน้าแล้ว รหัสตรง · ไม่ใช่ Parttime · ไม่ใช่วันหยุดของเขา · ถ้าจะเช็คจอ KPI ด้วย ให้เลือก**พนักงานหน้าร้าน** ไม่ใช่ตำแหน่ง ครัว ล้างจาน สไลด์ ซึ่งจอ KPI ซ่อนไว้ kpi.html:597) ให้สแกน**เข้างานจริง** 1 ครั้ง จดชื่อและเวลาไว้
3. **เปิด** `https://steep-hill-7d52.thananantpatt.workers.dev/report/check` ดูหัวข้อ "เครื่องสแกน -> สาขา" ต้องเห็น SN เครื่องใหม่พร้อมจำนวนครั้ง (worker.js:621-626)
   - ขึ้น "⚠️ ยังไม่ผูกสาขา!" = จด SN นี้ไว้ แล้วผูกในข้อ 3 (สำหรับ Hikvision นี่คือ SN จริงที่ต้องใช้)
4. **ดูเวลาที่บันทึก** (อ่านอย่างเดียว) ต้องตรงกับเวลาที่จดไว้ วันที่ต้องถูก:

```sql
-- สแกนล่าสุดของเครื่องใหม่ (อ่านอย่างเดียว)
select emp_code, punch_date, punch_time, verify_mode, source
  from punches
 where device_sn = 'ใส่ SN ของเครื่องใหม่ตรงนี้'
 order by punch_date desc, punch_time desc
 limit 20;
```

5. **เช็คว่าไม่มีพนักงานเกิดใหม่โดยไม่ตั้งใจ** (อ่านอย่างเดียว · เปลี่ยน `0` เป็น id ที่จดไว้ในข้อ 0 ข้อ 6):

```sql
-- พนักงานที่เกิดหลังวันติดตั้ง (อ่านอย่างเดียว)
-- ถ้าขึ้น error ว่าไม่มีคอลัมน์ start_date ให้ลบ "start_date," ออก
select id, code, nick, full_name, branch, start_date,
       case when nick = code then '⚠️ ระบบสร้างเอง (รหัสในเครื่องไม่ตรง?)' end as "เตือน"
  from employees
 where id > 0
 order by id desc;
```

6. **(Hikvision) ดูข้อมูลดิบ**: Supabase → Table Editor → ตาราง `device_log` → กรอง `path` = `/hik` → เรียงจากใหม่ไปเก่า ดูช่อง `body` (worker.js:63-64, 923-930)
   - **มี `deviceID` หรือ `macAddress` ไหม** ถ้าไม่มี ระบบจะใช้ IP ในวง LAN เป็นรหัสเครื่อง → IP ต้องไม่ซ้ำกับ Hikvision เครื่องอื่น (ข้อ 2B) · ถ้า SN ออกมาเป็น `HIK` ห้ามผูกสาขา แจ้ง Claude
   - ขึ้นต้นด้วย `{` หรือมี JSON อยู่ข้างใน (ถ้าขึ้นต้นด้วย `<?xml` / `<EventNotificationAlert` = เครื่องส่ง XML ดูข้อ 5)
   - `dateTime` ลงท้ายด้วย `+07:00` ไหม
   - สแกน 1 ครั้งได้กี่แถว (ควรได้ 1 แถว)
   - ช่อง `sn` ของแถว Hikvision จะว่าง เป็นปกติ (Worker จด sn จาก `?SN=` ซึ่ง Hikvision ไม่ส่งมา)
7. **ผูกสาขาด้วยการ์ด 📟 (ข้อ 3)** → หน้า 📊 วันนี้ ชื่อคนนั้นต้องขึ้นว่าเข้าแล้ว ในการ์ดของสาขาที่ถูก (ผูกผ่านการ์ดแล้วแอปเครื่องนั้นคิดใหม่ทันที payroll.html:7620-7621 · สแกนใหม่ขึ้นเองแบบ realtime payroll.html:7389-7400)
8. **ตอนคนเดิมสแกนออกงานจริง** (สิ้นกะ) ต้องเห็นเวลาออก
9. **สาขา 3**: ทำรายการในเส้นทางสาขา 3 ขั้น H เพิ่ม (รายงาน LINE · จอ KPI · ออฟฟิศ AI)

| ดูที่ | ผลที่ควรเห็น |
|---|---|
| การ์ด 📟 / `devices` | เครื่องใหม่อยู่ใน "เครื่องที่ผูกสาขาแล้ว" · `branch` เป็นรหัสสาขา · (ZK) ส่งข้อมูลล่าสุดไม่กี่นาที |
| `/report/check` | SN ใหม่ + จำนวนครั้ง + ชื่อสาขา ไม่มี ⚠️ |
| `punches` | วันที่/เวลาตรงกับที่สแกนจริง · `source` = `device` |
| `employees` | SQL ขั้น 5 ไม่มีแถวที่ไม่ได้ตั้งใจเพิ่ม |
| แอป หน้าวันนี้ | ชื่อขึ้นในการ์ดสาขาที่ถูก ไม่มีป้ายข้ามสาขาแปลก ๆ |

> **หน้า `/debug` ไม่ได้ตรวจเครื่องสแกน** มันเช็คแค่ secret กับฐานข้อมูล และจะเขียนแถว `sn = 'DEBUG-TEST'` ทิ้งไว้ในตาราง `devices` (worker.js:932-983, 956) ซึ่งจะไปขึ้นในการ์ด 📟 เป็นเครื่องที่ยังไม่ผูกสาขา **ไม่ต้องผูก** และทำให้กล่องเตือน "ยังไม่ผูกสาขา" นับเกิน 1 เครื่องตลอด (ข้อ 3) · ใช้หน้านี้ได้แค่ตอนสงสัยว่า Worker หรือฐานข้อมูลเสีย หรือตรวจหลัง Deploy (ขั้น C)

### ถ้ามีสแกนทดสอบเกิน (ช่างหรือพนักงานลองสแกนหลังชี้มาที่ Worker)

1. จดชื่อ + วัน + เวลาของสแกนที่ไม่ใช่เวลาทำงานจริงทุกครั้ง
2. **หลังคนนั้นสแกนออกงานจริงของวันนั้นแล้ว** (หรือเช้าวันรุ่งขึ้น) และก่อนปิดงวด: แอปเงินเดือน → ข้อมูลพนักงาน → คนนั้น → แท็บเวลาทำงาน → ✎ ของวันนั้น (payroll.html:5389)
   - วันที่เขาทำงานจริง: ใส่เวลาเข้า-ออกจริง แล้วกดบันทึก · การบันทึกจะ**ลบสแกนทั้งวันกะนั้น**แล้วเขียนแค่เวลาเข้า-ออกที่ใส่ (payroll.html:4771-4781, 4796-4819) สแกนทดสอบจึงหายไปด้วย · เวลาที่แก้มือไม่มี SN เครื่อง วันนั้นจึงจับข้ามสาขาไม่ได้
   - วันที่เขาไม่ได้ทำงาน: กด 🗑 ลบเวลาทั้งวันนี้ (payroll.html:2117, 4826-4837) · ปุ่มนี้ลบทั้งวันกะ ถ้าวันนั้นมีเวลาจริงอยู่ด้วยให้ใช้วิธีบนแทน
3. อย่าแก้ระหว่างที่คนนั้นยังทำงานอยู่ สแกนออกจริงที่เข้ามาทีหลังจะต่อท้ายเวลาที่แก้ไว้

### ช่องทางสำรอง: นำเข้าไฟล์ .xlsx จากเครื่อง (ใช้ด้วยความระวัง)

**สแกนเครื่องเดียวต่อครั้ง** จอลูกค้า (KPI) นับว่าใครยังอยู่ในร้านจากจำนวนสแกนในวัน เลขคี่ = ยังอยู่ (kpi.sql:278-290) ถ้าตอนเข้าสแกนทั้ง 2 เครื่อง (คนละนาที) จะกลายเป็นเลขคู่ แล้วจอลูกค้าจะซ่อนชื่อคนที่ยังทำงานอยู่ · สแกนในนาทีเดียวกันไม่เป็นไร ระบบนับเป็นครั้งเดียว (worker.js:860, 866-870)

### รับพนักงานใหม่หลังมีหลายเครื่อง (รวมสาขา 3)

คู่มือ PDF หน้า 10 ข้อ 4.1 ให้ลงหน้าที่เครื่องแล้วให้ระบบสร้างพนักงานให้ตอนสแกนครั้งแรก (worker.js:882-883) แต่พอมีหลายเครื่อง แต่ละเครื่องเสนอ User ID ถัดไปของตัวเองแยกกัน พนักงานใหม่ 2 คนที่ลงคนละเครื่องอาจได้รหัสเดียวกัน แล้วเวลาของคนที่ 2 ไปรวมกับคนแรกเงียบ ๆ (worker.js:877-880) และคนที่ระบบสร้างให้จะไม่มีสาขา (worker.js:897-900) จึงให้ทำแบบนี้แทน:

1. **ออกรหัสจากที่เดียว**: ฟอร์มในแอปไม่ได้ออกเลขให้ (เว้นว่าง = `M` ตามด้วยเลขเวลา payroll.html:4683) เจ้าของต้องตั้งเลขเอง ตามกติกาในขั้น E: **ตัวเลขล้วน ไม่ขึ้นต้นด้วย 0 ยาวไม่เกินที่เครื่องรับ และใช้ช่วงเลขของสาขานั้นโดยเฉพาะ** (เช่น สาขา 3 ใช้ 3001, 3002 … ตกลงช่วงเลขกับเจ้าของ)
   - **ก่อนกดบันทึก** เช็คว่ารหัสใหม่ยังไม่มีใครใช้ (ถ้าเช็คหลังบันทึก จะเจอคนที่เพิ่งเพิ่มเอง):

```sql
-- อ่านอย่างเดียว · คำสั่งแรกต้องได้ 0 แถว · คำสั่งที่สองต้องได้เลข 0
select code, nick, active from employees where code = 'ใส่รหัสใหม่ตรงนี้';
select count(*) as "สแกนค้างของรหัสนี้" from punches where emp_code = 'ใส่รหัสใหม่ตรงนี้';
```

   - ผ่านแล้วค่อยเพิ่มคนในแอปพร้อมรหัสและสาขา (👥 พนักงาน → ＋ เพิ่มพนักงาน payroll.html:834 → ช่อง "รหัสพนักงาน (จากเครื่องสแกน)" payroll.html:1838)
   - **แจ้งผู้จัดการทุกสาขา (รวมลาดพร้าวและรัชดา) ให้เลิกใช้ ID ที่เครื่องเสนอ** ตามคู่มือ PDF ข้อ 4.1 ไม่งั้นเลขที่เครื่องเดิมเสนอต่อไปอาจชนกับเลขที่ตั้งให้สาขา 3
2. **ใส่รหัสเดียวกันในทุกเครื่องที่คนนั้นจะใช้** ห้ามใช้ ID ที่เครื่องเสนอให้
3. ลองสแกนหลังลงหน้า = เวลาจริง (ข้อ 2 "ถ้าต้องลงหน้าคนเพิ่ม") ให้ลงหน้าตอนเขาจะเข้ากะ แล้วใช้สแกนนั้นเป็นเวลาเข้างาน
4. ถ้าใช้วิธีนี้ต่อ ให้ Claude แก้คู่มือ PDF ข้อ 4.1 ให้ตรง

### ถ้าเจอพนักงานถูกสร้างซ้ำ หรือเวลาไปลงผิดคน

- **ห้ามกด 🗑 ลบพนักงาน** เพราะจะลบเวลาสแกนทั้งหมดของรหัสนั้นทิ้งถาวร (payroll.html:4753-4760)
- **ห้ามแก้รหัสในฟอร์ม ✎ เพื่อรวมคน** เพราะแก้แค่ `employees.code` เวลาสแกนเดิมไม่ย้ายตาม (payroll.html:4683, 4735-4738) · ยกเว้นคนที่ยังไม่เคยมีสแกนเลย (ข้อ 0 ข้อ 5)
- ลำดับแก้:
  1. แก้รหัสในเครื่องให้ตรง
  2. ให้ Claude เตรียม SQL ย้ายเวลาสแกนจากรหัสที่ผิดไปรหัสที่ถูก เป็นการแก้ข้อมูลจริง **เจ้าของต้องอนุมัติก่อน** (CLAUDE.md:10) แล้วค่อยจัดการแถวที่ซ้ำ
  3. **ZK: เช็คว่าเวลาสแกนเข้า `punches` ครบแล้ว แล้วลบบันทึกการเข้างานในเครื่องด้วย** ก่อนหรือพร้อมกับการย้าย/ลบในฐานข้อมูล · Worker ตอบ `Stamp=9999` คงที่ (worker.js:42, 78-81) เครื่องบางรุ่นอาจส่งประวัติในเครื่องขึ้นมาใหม่ตอนเริ่มเครื่องหรือต่อใหม่ (ขึ้นกับรุ่น ยังไม่ได้ทดสอบ) แถวที่ลบไปจะกลับมา และพนักงานซ้ำจะถูกสร้างใหม่ (worker.js:875-911)
  4. หลังแก้ `punches` ด้วย SQL ให้ทุกเครื่องที่เปิดแอปเงินเดือนกด 🔄 (ข้อ 5 แถวสุดท้าย)
- ถ้าเป็นรหัสทดสอบของช่างล้วน ๆ (ไม่มีใครใช้รหัสนั้นจริง) ปุ่ม 🗑 ลบได้ แต่ถามเจ้าของก่อนกด และลบผู้ใช้นั้นในเครื่อง + ล้างบันทึกการเข้างาน (ZK) ก่อน ไม่งั้นอาจถูกสร้างกลับมา

### ระยะยาว: ขนาดตาราง `device_log`

Worker จดทุกคำขอลง `device_log` (worker.js:64, 923-930) รวม `/getrequest` ที่ ZK ถามทุก 30 วินาที (`Delay=30` worker.js:42) ≈ 2,880 แถว/วัน/เครื่อง ช่อง body เก็บได้ถึง 4,000 ตัวอักษร (worker.js:927) และ `TransFlag=1111000000` (worker.js:43) อาจทำให้เครื่องส่งรูปสแกนมาด้วย · ใน repo ไม่มีงานลบ log เก่า เพิ่ม ZK อีกเครื่อง = ตารางโตเร็วขึ้นเท่าตัว · เช็คเดือนละครั้ง (อ่านอย่างเดียว):

```sql
select count(*) as "จำนวนแถว",
       pg_size_pretty(pg_total_relation_size('public.device_log')) as "ขนาด"
  from device_log;
```

ถ้าจะลบ log เก่า **ต้องถามเจ้าของก่อน** (ลบข้อมูลจริง)

## คำถามที่ต้องตอบก่อนเริ่ม

คำตอบที่ได้แล้ว (2026-10-20): เครื่องใหม่**ยังไม่ได้ซื้อ ยังไม่รู้ยี่ห้อ** · ติดที่**สาขา 3**

1. **สาขา 3 เปิดในระบบแล้วหรือยัง** และใช้รหัสอะไร (เส้นทางสาขา 3 ขั้น A) · ถ้ายังไม่เปิด: **รหัส ชื่อ วันเปิดร้านจริง และสาขาภาษี** จะใช้อะไร (แก้ในแอปทีหลังไม่ได้ ขั้น B)
2. **เครื่องที่ใช้อยู่ที่ลาดพร้าวและรัชดาเป็นยี่ห้อ/รุ่นอะไร** (ดูที่ตัวเครื่อง + SQL ในหัวข้อ "ควรซื้อเครื่องรุ่นไหน") แล้วจะซื้อรุ่นเดียวกันได้ไหม
3. **ร้านขายตอบเช็กลิสต์ข้อ 1–5 ผ่านไหม** · ยี่ห้ออื่น = แจ้ง Claude ก่อน
4. **Worker ใน Cloudflare เป็นรุ่นใหม่ไหม** (ค้น `pnl_branches` · บังคับ) และตั้ง secret `BRANCH_MAP` ไว้หรือเปล่า (ถ้าตั้ง ค่าเป็นอะไร)
5. **พนักงานสาขา 3 มีใครบ้าง** ใครเป็นคนใหม่ (ใช้ช่วงเลขรหัสอะไร ขั้น E) ใครย้ายมาจากสาขาเดิม (ใช้รหัสเดิม · ย้ายวันไหน ถ้ากลางงวดจะแบ่งทิปอย่างไร) และมีใครย้ายมาจาก OFFICE ไหม (ถามก่อน เพราะรอบงวดเปลี่ยน)
6. **ใครเป็นผู้จัดการสาขา 3** และจะให้เพิ่มพนักงาน/ผูกเครื่องเองไหม (ขั้น B2)
7. **คนสังกัดสาขาอื่นจะมาสแกนเครื่องสาขา 3 ด้วยไหม** (จะนับเป็นข้ามสาขา ไม่มีผลกับเงินเดือน)
8. **สาขา 3 มีเน็ตที่จุดติดเครื่องแล้วหรือยัง** (ขั้น F0)
9. **ช่างลงหน้าวันไหน** และ**พนักงานมาทำงานจริงครั้งแรก (เตรียมร้าน/อบรม) วันไหน** — ต้องลงหน้าให้เสร็จก่อนชี้เครื่องมาที่ Worker (ข้อ 1 → 2) · เพิ่มพนักงานในแอปให้ใกล้วันลงหน้า และทดสอบในวันทำงานจริงก่อนวันเปิดร้าน (ขั้น E และ H)
